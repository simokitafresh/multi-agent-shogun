# Obsidianリンク×セマンティクスインデックス 分離原則

<!-- created: 2026-05-22 | origin: 殿×将軍×軍師 対話で確立 -->

## What（何を決めたか）

Obsidianリンクとセマンティクスインデックスは**別の道具**。融合禁止。分離して使う。

| | セマンティクスインデックス | Obsidianリンク |
|--|---|---|
| 本質 | 検索の入口 | 知識ネットワークの道 |
| 機能 | 概念名/aliases → ファイルを見つける | ファイル間の直接的関係を表す |
| 生成者 | 機械(aliases自動蓄積) | 忍者(読んで理解して張る) |
| 価値 | 知らないファイルを発見できる | 距離×濃度で関係の強弱がわかる |

### 2026-06-03 長期運用原則

詳細: `docs/research/three-layer-memory-operating-principles_20260603.md`

三層記憶は「LLMへ一時文脈を渡す補助」ではなく、人間とLLMが共有する外部認知基盤である。
SQLiteは記憶台帳、Obsidianは人間の認知編集層、セマンティック辞書は意味の橋として分離して使う。

- SQLite: 原文、断片、履歴、状態、参照関係を保持する。原文と要約/解釈/判断を混ぜない。
- Obsidian: 人間が読み返して思考を再開できる概念ノート、MOC、判断履歴だけを昇格する。全量同期禁止。
- セマンティック辞書: aliasesだけでなく、same_as / related_to / often_confused_with / should_not_merge_with 等の関係種別で過剰接続を防ぐ。
- 自動成長: LLM/自動処理は候補生成まで。統合、削除、現在知識への昇格は検証/人間確認/ロールバック可能性を前提にする。
- 想起制御: timestampが明確なら物理的忘却は原則不要。削除ではなく、アーカイブ、低優先度化、通常検索除外、Historical層移行を正式な機能として扱う。
- timestamp: 全記憶・全リンク・全状態変更に発生/観測/記録/検証/失効/置換/退避時刻を持たせ、因果を過去未来に辿れるようにする。
- レビュー統合: 軍師/将軍レビューにより、検索ログ収集、Obsidian↔SQLite同期、`should_not_merge_with`、events state、confidence/expires_at、contradiction_candidate、段階的な想起制御を次の実装設計課題として明記した。追加再監査により、実装前に殿の使用パターン、現実との差分、三層間同期コストを確認する。最新版の洗脳覚醒レビューにより、確認方法未定義・距離計測未記載・殿確認への他者依存・先送りを修正し、検索ログ収集は前提確認と並行着手可能とした。

## Why（なぜこの結論か）

- **Obsidianの本質 = 距離×濃度**。ファイル間の直接[[リンク]]でこそ、関係の近さ・遠さ・密度に意味が生まれる
- **ハブ方式(cmd_2955)で実証済みの失敗**: 概念名をハブにすると全ファイルが概念から1ホップ等距離。距離情報が消える。セマンティクスインデックスの検索構造をObsidianに複製しただけ。孤立率88%→85%の微改善で本質を破壊した
- **殿の言葉**: 「重要なことは本質に忠実かどうかだ。目先の利益にとらわれると大きな間違いをする」

## Who（誰がやるか）

## How（どうやるか）

### 合意6点

1. **分離**: セマンティクスインデックス=target選択のみ。リンク行為には不関与
2. **理解の外部化**: 忍者は対象+関連ファイルを読む。リンクは理解の記録（ノルマなし）。書かなければ理解は/clearで消える（Phase 4: 自動化×強制）
3. **還流禁止**: リンク結果をセマンティクスインデックスに還流しない。距離×濃度が壊れる
4. **急がない**: 品質保証された少数 > ノイズ混じりの大量。+1点の複利
5. **計測は後回し**: まず回す。計測設計を先行すると指標最適化に走る
6. **ACに記録を含める**: 「発見した関連を[[リンク]]として記録せよ」は知性の外部化であり目的化ではない

### 禁止事項

- **ハブ方式禁止**: 概念名をハブにした`semantic-links:`行の挿入。全ファイル等距離化=距離情報破壊
- **自動リンク生成全般禁止**: 方式を問わず(キーワードベース/共起ベース/LLM推論ベース等)、機械的リンク生成は品質保証ができない。忍者が読んで理解して張る=唯一の品質保証手段
- **リンクノルマ禁止**: ACに「リンクをN本張れ」。数の最適化でノイズリンクが生まれる
- **還流禁止**: Obsidianリンクの結果をindex.mdのresourcesに追加。等距離問題の再発
- **理由ノルマ禁止**: 「リンクの理由を書け」。LLMは理由を捏造する

### リンク形式ルール

- **[[ファイル名]]形式**（パスなし）。Obsidianのshortest path matchingに準拠
- 同名ファイルが存在する場合のみ[[パス/ファイル名]]で曖昧性を解消

### 品質検証

- bcの自己申告だけでは不十分（LLMは読まずにbc:yesと書ける）
- **リンク先ファイルの特定行引用**を報告に含める（捏造困難）
- files_modifiedにリンク先ファイルが含まれることを確認

### 修行での使い方

```
1. セマンティクスインデックスで修行target選択（孤立ファイル優先）
2. 忍者がtargetファイルを読む → 理解する
3. semantic_search.shで関連候補を発見（補助ツール。検索=入口、判断=忍者）
4. 忍者が関連ファイルも読む → 本当に関連があるか判断
5. 関連が確認できたら直接[[ファイル名]]リンクを張る
6. リンクは理解の記録。ノルマなし。リンク先の特定行を報告に引用
7. バックリンク確認: bash scripts/causal_backlinks.sh "ファイル名" で逆参照を確認可能
```
