## Phase 2: なぜ信頼度top1は負けるのか

confidence = median_return / uncertainty。top1=「最も確信度が高い1つのPF」。

確信度が高い = FLAIRのLevel×Shape構造がきれいに当てはまる = **安定だが必ずしも高リターンではない**。

momentum top1は「最もリターンが高いPF」に集中。信頼度top1は「最も読めるPF」に集中。**読めるPFと儲かるPFは違う。** だからtop1同士ではmomentumが勝つ。

## Phase 3: なぜ信頼度top2/top3は圧勝するのか

top1→top3でCAGR 16.6%→29.6%(+78%)。この跳躍は単純な分散効果では説明できない。

**仮説**: 信頼度top2/top3は「信頼できるPF群」を選んでいる。つまり信頼度rankingは**PF品質フィルタ**。ノイズの多いPF(FLAIR構造に当てはまらない=予測困難)を除外し、構造が安定したPF群に分散投資する。

**検証**: LOO残差(cmd_1718)でSpearman=0.46が出ている。LOO残差小=安定=信頼度高。信頼度ランキング上位のPF群は構造的に安定しているPF群。安定なPFに分散→各PFの予測が当たる確率が高い→分散しても品質が劣化しない。

## Phase 4: なぜbinary gateは効かないのか

cmd_1718検証5(不確実性gate): CI > 中央値 → Cash → **悪化**。
cmd_1719(信頼度ranking top3): → **圧勝**。

同じFLAIR確率予測データなのに結論が逆転。

- **gate = 情報を捨てる**。「この月はダメ」と判定 → PF×時間の2次元情報を時間1次元に圧縮
- **ranking = 情報を保つ**。「この月はこのPF群が信頼できる」→ PF×時間の2次元を活かす

→ **binary判定は常にranking判定に劣る**。gateは情報量を減らす操作。有効な要素も閾値以下なら全部捨てる。rankingは相対序列を保存する。

## Phase 5: なぜmomentumは集中有利でFLAIR信頼度は分散有利か

| 属性 | momentum | FLAIR信頼度 |
|------|----------|------------|
| 測定対象 | 方向の強さ(過去リターン) | 構造の安定性(予測確からしさ) |
| top1の意味 | 最も上昇中のPF | 最も読めるPF |
| 集中の効果 | 方向が続けば大勝ち | 安定だが低リターン |
| 分散の効果 | 方向が薄まる | **品質を保ったまま分散** |
| 最適戦略 | 集中(top1>top2) | 分散(top3>top2>top1) |

**根因**: momentumは「信号の強さ」を測る。強い信号に集中するのが最適。信頼度は「信号の品質」を測る。品質が高い信号を複数束ねるのが最適。**強さと品質は異なる測定次元。**

## Phase 6: なぜ各論は天井が低いのか

今日の5部品各論(cmd_1718):
- Ridge前向き予測 → 弱い(τ=0.01)
- Shapeゲート → 混在(CAGR悪化)
- Box-Cox → 部分的(ranking安定化のみ)
- 不確実性ゲート → 悪化

**なぜ**: 全て「個別PFにFLAIRの部品を当てる」実験。個別PFの改善 = Phase 17の壁の再現。PF単体を磨いてもFoFで相殺される。

**一方で効いたもの**: 信頼度ranking(cmd_1719) = 65PF横断のランキング。LOO残差(cmd_1718検証3) = 65PF横断の品質フィルタ。Shape相関(軍師分析) = 65PF横断のペアリング。

→ **FLAIRの部品を個別PFに当てるのは弱い。65PF横断の構造分析に使うのが強い。**

## Phase 7: 根本原理

```
Ward(97.2%支配) = リターン相関に基づくPF群の構造
                ↓
selection block(2.8%) = 各論(lookback/top_n/方式)
                ↓
    天井が低い。各論を磨いても2.8%の中の改善
```

FLAIRが開けた新しい道:

```
Ward(リターン相関) ←→ Shape(季節相関): 直交する構造軸
momentum(空間: どのPFが強いか) ←→ 信頼度(時間: いつ信頼できるか): 直交する選択軸
                ↓
    3軸: 構造(Ward or Shape) × 空間(momentum) × 時間(信頼度)
    各軸が独立(Kendall τ弱) → 組み合わせで情報量が乗算的に増える
```

**各論(PF単体改善)が効かない理由**: 1次元の改善はFoFの多次元構造で吸収される。
**構造(PF群設計)が効く理由**: 構造は全PFに同時に影響する。Ward→全PFのクラスタが変わる。信頼度ranking→全PFの選択順序が変わる。

## 結論(1文)

FLAIRは「PF個別の前処理ツール」ではなく「PF群の構造分析ツール」。部品を個別PFに当てるのは弱い。部品を65PF横断のランキング・クラスタリング・ペアリングに使うのが正しい。
