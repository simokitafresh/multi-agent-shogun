# 将軍inbox盲点 — なぜなぜ7回

殿指示(2026-04-16): 「掲示板投稿が将軍に届く仕組みは動いているか？→実際に気づかないと仕組みの意味がない→まずなぜなぜ7回」

## 事実

- bulletin_write.sh L110-121: 投稿者以外の将軍・家老・軍師にinbox_writeで自動通知(動作確認済み)
- 将軍inbox: bulletin_notify 4件中3件がread: false
- inbox_watcher.sh: 稼働中(PID 1696051, shogun:main)

## なぜなぜ7回

| # | なぜ | 回答 |
|---|------|------|
| 1 | なぜ将軍が掲示板投稿に気づかない？ | inbox未読3件が溜まっている。将軍がinboxを処理していない |
| 2 | なぜinboxを処理していない？ | inbox_watcherはnudge送信済みだが、将軍が殿との対話中でnudge処理できない |
| 3 | なぜnudge受信してもinboxを読まない？ | 殿の入力が来ると将軍はその処理に集中。nudgeは入力バッファに埋もれる |
| 4 | なぜ作業中にinboxを処理しない？ | CLIの入力は殿が占有。将軍は次の自分のターンまで処理不可 |
| 5 | なぜ次ターンでもinboxを処理しない？ | 殿の新しい入力に対する処理が最優先。inbox確認を強制する仕組みがない |
| 6 | なぜ将軍にstop hookがない？ | 殿の入力を妨げるリスクを回避するため未導入(忍者・軍師にはstop_check_inbox.shあり) |
| 7 | **根因: 殿の入力を妨げずに将軍に気づかせる仕組みが設計されていない** | nudge送信は「最後の1マイル」が欠落。殿対話中→気づかない→次ターン→新しい殿入力→またスキップの無限ループ |

## 因果鎖

```
掲示板投稿 → inbox_write(OK) → watcher nudge(OK) → 将軍受信(?) → 処理(×)
                                                      ↑
                                          殿との対話中はnudgeが埋もれる
                                          次ターンでもinbox確認の強制がない
                                          = 気づきの「最後の1マイル」が欠落
```

## 解決案

### 案A: 将軍PostToolUse hook(推奨)

将軍が任意のツール使用後にinbox未読件数を1行注入。殿の入力は妨げない(PostToolUseは将軍の応答中に発火)。

```
# .claude/settings.json PostToolUse hook
# 対象: shogunペインのみ
# 出力: "📨 shogun inbox: 3 unread" (未読>0時のみ)
```

防御レベル: L4(フロー内埋込)。意志依存ゼロ。

### 案B: session_start_inject.sh強化

起動時だけでなく、将軍の応答が生成されるたびにinbox件数を注入。ただしPostToolUseより粒度が粗い。

### 案C: ntfy通知(殿向け)

bulletin投稿時にntfyで殿のスマホに通知。将軍ではなく殿が気づいて将軍に読ませる。ただし殿の手間が増える。
