## §1 監査観点(第一段階の全教訓の運用形)

各検知器に以下の7問を適用する。全て第一段階で実データ実証済みの原理:

| # | 問い | 由来 |
|---|------|------|
| A1 | **実体宣言**: 判定に使う値は実体か写しか(キャッシュ/index/報告側コピー/古い値/形式前提/**別種の値のカテゴリ誤り**)を明示しているか。★比較演算は**両辺の時計の意味が同じか**を確認(「作業が終わった時刻」vs「データが書かれた時刻」の大小比較=意味の違う2つの写しの比較。WAL構造でコピー66秒級なら競合なしでも構造的に取りこぼす実証)。**是正の最強形=時計を捨てて内容の水位(max(rowid)等)で比較する** — 揃える先の時刻自体が信頼できない場合、時刻の意味統一より水位比較が強い(B45、疾風が将軍の原理を上書き) | E型統一原理、B38、三層記憶cache鮮度(blt_053045) |
| A2 | **陽性対照**: 既知の陽性1件を検出できることを実データで示したか(N=1で可・合成は明記)。★是正の検証では**減少数だけでなく残存数を確認せよ** — 壊しても数値は下がる。残存数(検出機能が生きている証明)がそれを分ける(B42検証: OLD=7/NEW=6、0件なら機能破壊だった) | 軍師設計+B42運用形 |
| A3 | **陰性対照**: 破壊系・除外系は保護対象との積集合0件を数値で示したか。**陰性が本体**(脱出経路が抜け道になっていないこと) | worktree42件の破壊未然防止、B26-28 |
| A4 | **記録≠状態**: 記録の存在を問題の現存と同一視していないか。終端値(N/A墓標)を持つか。**成功も検査対象**。★軍師の3分類で危険度を区別せよ: **(a)タイムラグ型**(実体は正しく検証済み→時刻確認手順で足りる) **(b)誤読型**(実体を見れば分かる) **(c)判定不能の偽装型**(検証が実行されていないのに結果が記録される=**唯一、実体を見ても気づけない型**。single-flight競合3件が実例。統計・成績表を汚染しうるため監査最優先) | 族5例+T-AC3-1+軍師3分類(blt_051944) |
| A5 | **同時性**: 多エージェント+デーモン環境で壊れないか(編集中ファイルの実行/HEAD高頻度変動/共有index/自動再生成レース) | 疑い5-7、B19/B27、GA-341/344/348 |
| A6 | **出口明示**: BLOCK文言は1行で出口を示すか(示せないものは対象外でよい=過剰防止条項)。**test名に条件と期待結果が入っているか** | B39+軍師「test名=仕様書」 |
| A7 | **合成無害**: 他ガードとの同時成立で出口ゼロにならないか(「既知の詰まり1件で脱出経路が残ることの確認」fixture) | 合成デッドロック族5例 |
| A10 | **到達可能性**: コードが存在することと、そのコードに実行が到達することは別物(「実装の有無」≠「実効性の有無」)。実装(2)はD010/G2を持つが入力分割機構がなく判定に到達しないケースがある実証(B44)。配線(md5 vs grep)・テスト対象(名乗り vs source先)・記録≠状態と同じ族の最内層 | B44(blt_075119)。テスト移植時は移植後の実行確認必須(別経路で結果が変わりうる) |
| A9 | **実行環境独立性**: その検査は誰がどこで実行しても同じ結果を返すか。実行環境が検査対象を変えないか(TMUX_PANE自動絞り込みで「tmux pane内の実行者=エージェント全員だけがFAILしCIはPASS」した実証=CIは我々の実行環境を再現していない。観測者が原因になる型の親戚: あちらは再実行が現象を作り、こちらは実行者の環境が結果を変える) | B45真因(blt_065927)。対処=hermetic化(env -i等)は機序特定とセットで |
| A8 | **沈黙の検査**: 検知器が黙っていることを問題がないことの証拠にしていないか。**騒ぐ検知器の欠陥は見つかるが、黙る検知器の欠陥は見つからない** — 陰性対照を持たない検知器は自分の見逃し(false negative)を検出できない | B42同型2件目(CLEARラッチ素通り=誰も観測していなかった見逃し、疾風07-26) |

**監査者の規律**(confirmed_scope 3形+統一根): 範囲外へ結論しない/範囲の選定理由を書く/分類も判断である/**値と出所を対で書く**(測定時HEAD・根拠実文言)。
**★最重要 — 教訓の逆説(07-26。誤り35件=軍師7件は実証・家老28件は自己申告でうち機序確認5件のみ — 内訳併記は両者の範囲宣言による)**: 全誤りの共通構造=「仮説に合う断片を見つけた時点で確認を終える」。特に**過去の教訓とパターンが一致したときこそ確認を薄くする**(一致=仮説の生成であって検証ではない。MEMORY.md無知の知原則「原理は仮説生成に使え、結論に使うな」の実証35件)。教訓が増えるほど一致が増え確認が薄くなる — 本監査で立てる教訓群自体が同じ罠になる。対策=手順1つ: **「何かを発見したと感じたら、当てはまらない可能性を1つ挙げてから報告する」** — 発火条件は「発見の感覚」(誤り事例の全てに伴っていた内部状態=自分で検知できる合図。「投稿前に毎回」は広すぎて守れない)。**AC設計の仮説汚染=実測が効かない唯一の型(07-26軍師)**: 忍者は与えられたACの枠内で報告するため、ACの選択肢が閉じていれば(2択等)第3の要因が支配的でも報告する枠が無い — 監査者の実測では潰れず、**draftレビューでしか捕まらない**。∴レビュー最優先項目=「選択肢が閉じていないか」(2択なら第3を問う/「AかBか」なら「どちらでもない」が報告可能か)。B44のAC2の2択がA10発見を遅らせた実例。 **打ち切りの誤認(07-26)**: 観測の打ち切り点を事象の終端と誤認するな — 「事象が起きなかった」と確定できるのは区間が閉じた場合のみ。末尾の未完了区間は判定に数えない(生存分析のcensoringと同型)。対=「記録の空白≠事象の不在」。 突合項目を増やすな・多段化禁止・**対策として教訓を増やすこと自体が次の罠** — 正確な基準は「既存で足りるなら増やすな」(軍師・家老とも同一基準。軍師は既存で足りたため登録せず、家老は逆説そのものが未登録だったため1件登録=条件が違っただけで判断は分かれていない。軍師の実測突合で確定)。
