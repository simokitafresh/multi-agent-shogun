## §1 監査観点(第一段階の全教訓の運用形)

各検知器に以下の7問を適用する。全て第一段階で実データ実証済みの原理:

| # | 問い | 由来 |
|---|------|------|
| A1 | **実体宣言**: 判定に使う値は実体か写しか(キャッシュ/index/報告側コピー/古い値/形式前提/**別種の値のカテゴリ誤り**)を明示しているか | E型統一原理13+例、B38 |
| A2 | **陽性対照**: 既知の陽性1件を検出できることを実データで示したか(N=1で可・合成は明記) | 軍師設計・lens型4/5有効 |
| A3 | **陰性対照**: 破壊系・除外系は保護対象との積集合0件を数値で示したか。**陰性が本体**(脱出経路が抜け道になっていないこと) | worktree42件の破壊未然防止、B26-28 |
| A4 | **記録≠状態**: 記録の存在を問題の現存と同一視していないか。終端値(N/A墓標)を持つか。**成功も検査対象**(緑になった経路を見たか。異常に遅いPASSを監査したか) | 族5例+T-AC3-1汚染PASS |
| A5 | **同時性**: 多エージェント+デーモン環境で壊れないか(編集中ファイルの実行/HEAD高頻度変動/共有index/自動再生成レース) | 疑い5-7、B19/B27、GA-341/344/348 |
| A6 | **出口明示**: BLOCK文言は1行で出口を示すか(示せないものは対象外でよい=過剰防止条項)。**test名に条件と期待結果が入っているか** | B39+軍師「test名=仕様書」 |
| A7 | **合成無害**: 他ガードとの同時成立で出口ゼロにならないか(「既知の詰まり1件で脱出経路が残ることの確認」fixture) | 合成デッドロック族5例 |
| A8 | **沈黙の検査**: 検知器が黙っていることを問題がないことの証拠にしていないか。**騒ぐ検知器の欠陥は見つかるが、黙る検知器の欠陥は見つからない** — 陰性対照を持たない検知器は自分の見逃し(false negative)を検出できない | B42同型2件目(CLEARラッチ素通り=誰も観測していなかった見逃し、疾風07-26) |

**監査者の規律**(confirmed_scope 3形+統一根): 範囲外へ結論しない/範囲の選定理由を書く/分類も判断である/**値と出所を対で書く**(測定時HEAD・根拠実文言)。
