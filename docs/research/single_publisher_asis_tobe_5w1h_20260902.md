## §2 ToBe
### 2.1 原則
1. origin/main へ commit を到達させる経路は **flock 1 本**(`$STATE_DIR/publish.lock`)で直列化する。lock の中で commit+push するのは publisher daemon(家老 lane、FIFO queue)と、将軍・家老の直接 commit wrapper(U1b)の 2 種のみ。忍者・daemon 群・台帳 writer は publisher 経由。
2. 忍者は自分の worktree で **local commit(immutable 成果物)** まで。origin DAG に忍者の ancestry は入らない。成果物の定義(家老レビュー 4)=**`source_tree`(local commit の tree id)+`patch_sha`(base..source の scope 限定 patch の sha256)+`published_sha`(publisher が生成した直線 commit)**の 3 つ組。旧契約 field の写像: `commit_hash`→`source_sha`(local commit id、参照のみ)/ test receipt の `source_head`→`source_tree` / **task・AC fingerprint は指示契約の同一性、`patch_sha` は成果物の同一性=別物として両方保持** / `cross_repo_commits`→ `{repo, ref, source_sha, published_sha, path receipt}` の組(path 一覧だけに縮退しない)/ ci_fix の `source_commit`→`published_sha` / worktree cleanup→artifact 複製(C6)後に許可。
3. publisher は source commit を merge/cherry-pick せず、`base..source` の **scope 限定内容(path/blob)を最新 remote tip へ適用し新しい直線 commit** を作る(家老案)。conflict=忍者へ rebase 差し戻し(可視)。
4. 台帳(insights/bulletin/workarounds/lessons/semantic-map)は publisher 内の **独立 batch commit**(code commit と混ぜない、因果時刻を保つ)。writer は root worktree へ書かず **`$STATE_DIR/ledger_inbox/`(絶対境界)へ追記**し、publisher が batch 時に取り込む(家老レビュー 2: root porcelain を常時 0 にするため)。
5. 1 task = 1 published commit = 1 push。CI は published_sha に紐付く。
6. origin への commit+push は **`$STATE_DIR/publish.lock` の flock を保持している間だけ**行う(publisher daemon と直接 commit wrapper の 2 呼出し元)。全 pane・daemon が同一マシン・同一 Unix user で動くため、flock が直列化の必要十分条件。署名付き占有 file・push 時の検査 hook・認証の分離は**採らない**(殿 14:02『本質に戻ろう』)。lock を取らない push が混入した場合: ff なら履歴は直線のまま(無害。publisher の次 cycle の tip 再取得で吸収)、non-ff は origin が拒否、merge commit を作る経路は U7 で停止済み。検知は C1(merge 0)ではなく **commit trailer `Published-By: publisher|wrapper`** の欠落で行う(C1a)。lock の critical section は **自分で有界**にする: `lock-run` は command 全体を `timeout <bound>`(publisher 600s、wrapper 300s)で実行し、内部の `git fetch`/`git push` も各 `timeout 120`。上限到達時は GNU timeout が自分の作った process group 全体へ TERM→KILL を送る(shim・publisher は信号送出コマンドを書かない=D006 準拠)。group 消滅後に shim が done receipt を書いて exit し flock は kernel が解放する。publisher は lock-run の rc=210(timeout 専用)を検知し isolated tree を破棄、request を queue 先頭へ戻す(冪等)。daemon_watchdog は『プロセス不在』のみで再起動し、他プロセスを 信号送出コマンドを使わない。

### 2.4 契約(二値)
- C1: origin/main の新規 commit の親数は常に 1(`git log --merges origin/main --since=<canary 開始>` = 0)。
- C1a: origin/main の新規 commit の **各 commit に trailer `Published-By: publisher|wrapper` がちょうど 1 行**(record-safe 判定(trailer **総数**=1 ∧ その唯一値が許可値): `git rev-list origin/main --since=<canary 開始> | while read h; do t=$(git log -1 --format='%(trailers:key=Published-By,valueonly)' "$h" | sed '/^$/d'); n=$(printf '%s\n' "$t" | sed '/^$/d' | wc -l); { [ "$n" = 1 ] && printf '%s' "$t" | grep -qxE 'publisher|wrapper'; } || echo "BAD $h n=$n"; done | wc -l` == 0。fixture 5 種(valid/duplicate/missing/wrong 値/mixed=publisher+intruder)で BAD 行 0/1/1/1/1(観点 42)。lock 外 ff push の検知はこれで行う(C1 の merge 0 では ff 迂回を検知できない、観点 30)。
- C2: 公開された commit の tree は、対応する忍者 source commit の scope path について blob 一致(path/blob receipt)。
- C2a: 適用前に **全変更 path で tip blob == base blob** を検証し、1 path でも異なれば publish 0 件+RC(忍者へ rebase 差し戻し)。最新 tip の同 path 変更を上書きしない(家老レビュー 2)。
