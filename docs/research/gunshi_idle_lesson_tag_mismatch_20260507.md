# 教訓タグシステム全面修正 (2026-05-07)

## 発見経緯
教訓効果率分析→tmux誤タグ54%→一部修正→殿指摘「一部対処は穴を残す」→全パターン修正

## なぜなぜ7回(殿指示)
1. なぜ一部だけ修正した？→tmux/wsl2は誤タグ率が高かったから「明確」と判断
2. なぜ他を放置？→計測で90%超の誤タグ率なのに「DETAILに含まれるから正当かも」と逃げた
3. なぜ逃げた？→全パターン修正は作業量が大きく、今やるべきか疑った
4. なぜ作業量で判断？→「低ROI」で正当化。殿原則「優先順位=実行順、全部やる」に反する
5. なぜ殿原則に反した？→「低優先=やらなくていい」と読み替えた。LG023を言い訳に悪用
6. なぜLG023を言い訳に？→原理の適用範囲を勝手に拡大(「新gate量産するな」≠「修正放置してよい」)
7. **根因**: パラメータ空間縮小禁止(CLAUDE.md)と同根。作業量を理由にスコープを縮小する構造的弱点

## 根因の構造
lesson_tags.yamlの全22タグに多義語パターン(render/window/session/test/report/process/block/clear/push/script/idle等)
→ TITLE+DETAILの全文マッチで一般語が頻出 → ほぼ全教訓に無関係タグ付与 → タグフィルタ実質無効

## 修正(全パターン・一括)
### Phase 1: 多義語排除
- 全22タグの多義語パターンを排除
- render/window/session/process/push/script/idle等の一般語を除去
- `\b`→日本語対応境界制御: `(?<![a-zA-Z])...(?![a-zA-Z])`
- 残すべきドメイン固有語のみ保持

### Phase 2: ドメインタグ追加(タグ0件率低減)
6タグ追加: fof/fullrecalculate/cdp/research/cache/grid_search(既存)
タグ0件率: 49%→21%

### Phase 3: 既存教訓retag
- universal誤タグ8件: L622-L636 retag完了(gs/fullrecalculate/git-ops)
- tmux誤タグ23件: retag完了(正当タグのみ残す)
- 残3件(L011/L068/L123): 旧フォーマットで--retag非対応。家老/lesson-sort対応

## 教訓

- パラメータ空間縮小禁止はcmd設計だけでなく全ての作業に適用される原理
