## 現状の問題点 — cmd_2904→2906→2907で実証

### 問題1: 既知の設計意図が修正時に参照されない

cmd_2904でCodex idle respawnをブロック → cmd_1150(STALL-GHOST安全弁)の設計意図を知っていれば過剰抑止は防げた。
**因果辺([[cmd_1150]])は存在したが、修正フローで参照する仕組みがなかった。**

### 問題2: 仮説が未検証のまま実装される

cmd_2906で「/newがidle時に動く」と仮定 → 実測せずに実装 → CTX滞留で失敗。
**因果ネットワークに「Codex CLIの/newはCLI内部task in progressで拒否される」という知識がなかった。**
→ 知識がなければ仮説を立てるが、仮説の検証を**強制する仕組み**もなかった。

### 問題3: 設計意図は事後にしか記録されない

設計意図カタログ(STALL-GHOST等4パターン)は調査後に作成。Codex respawnの設計意図(パターン1.5)はcmd_2907の殿裁定後に追記。
**設計意図はコード変更時に同時記録されるべきだが、現状はなぜなぜ7回で事後発見→手動記録。**

### 3問題の共通根因

**因果ネットワークの生成と消費が分離されすぎている。**
- 生成: cmd保存/報告/レビュー/教訓 → 4箇所(十分)
- 消費: deploy(忍者)+cmd_save(将軍) → 2箇所(**不足**)
- **コード変更時(=最も設計意図が必要なタイミング)に因果辺が参照されない**

## L7: 因果ネットワーク学習

**定義**: 因果ネットワークの密度と到達性が、未経験の問題に対する防御を自動的に提供するレベル。

**L6とL7の本質的違い**:
- L6: 「同じ失敗を繰り返さない」(過去の自分のパターン → 自分の次回)
- L7: 「**似た失敗を初めてでも回避できる**」(他者の経験+因果接続 → 未経験者の初回)
- L6: 点(個別パターン)。L7: 網(因果接続)

**L6とL7の本質的違い(5W1Hの対象シフト)**:
- L6の5W1H: 「1つの仕組み(gate/hook)が正しく回る条件」
- L7の5W1H: 「ネットワーク自体が学習を駆動する条件」

### L7の4つの機能

#### 1. 未経験の問題に先行知識を提供(既知の転写)
忍者がninja_monitor.shを触る
→ semantic_conceptsが関連概念(agent_formation_management + **infra_design_intent**)を自動注入
→ 忍者はSTALL-GHOSTをバグと誤認しない

**L6との違い**: L6はその忍者がSTALL-GHOSTを過去に経験した場合のみ注入。L7は未経験でも概念接続で到達。

#### 2. 横の因果接続(設計意図の衝突検知)
cmd_2904の過剰抑止 → [[cmd_1150]]のSTALL-GHOST設計意図に因果辺
→ 設計意図を知っていれば過剰抑止は防げた
→ **因果辺が「この修正はここの設計意図と矛盾しないか？」を自動表示**

**実証**: cmd_2904→2906→2907で3回修正。因果辺([[cmd_1150]])が修正フローに組み込まれていれば1回で正解にたどり着けた。

**L6との違い**: L6は同一忍者の過去失敗のみ。L7は別cmd/別忍者の経験が因果辺で接続。

#### 3. 経験の転写(因果鎖の共有)
設計意図カタログ: 「バグに見えるが正しい」5パターンの因果鎖
→ 調査者が追体験(なぜなぜ7回)せずに因果を辿れる
→ /clearで消えない。因果辺で接続された知識が永続する

**L6との違い**: L6は個人の弱点パターン(定量)。L7は因果鎖(構造)の転写。

#### 4. 仮説の崩壊記録(なぜ覆されたかのネットワーク化) ★cmd_2904-2907で発見

cmd_2906: 「/newがidle時に動く」仮説→CTX滞留で崩壊→殿裁定→cmd_2907で修正。
**崩壊した仮説とその理由が因果辺で記録されていれば、同じ仮説を別のエージェントが立てない。**

```
[[cmd_2906]] -> [[Codex_CLI_new_incompatible]] -> [[respawn_is_correct_design]]
```

この辺がネットワークに存在すれば、次に誰かが「/newで十分」と提案した時にcausal_backlinksが「Codex_CLI_new_incompatible」を返す。

**L6にないもの**: L6は「この忍者がこのパターンで失敗した」。L7は「**この仮説はこの理由で崩壊した**」。仮説空間の探索効率が上がる。

## L7の5W1H — ループを回す最小構造

L6の5W1Hは「1つの仕組みが正しく回る条件」。L7は「ネットワーク自体が学習を駆動する条件」。

| 要素 | L6(個の仕組み) | L7(因果ネットワーク) | 欠落時の実害 |
|------|---|---|---|
| WHY | なぜこの仕組みを作るか | **なぜこの因果辺が存在するか**(設計意図の理由) | cmd_2904: STALL-GHOSTの設計意図を知らず過剰抑止 |
| WHAT | 何を達成するか | **何と何が因果で繋がるか**(ノード間接続) | 概念↔概念の接続なし。43概念が孤立 |
| WHEN | いつ発動するか | **いつ因果辺が生成/消費されるか** | 生成4箇所。消費2箇所のみ。レビュー/idle時に消費なし=学習機会損失 |
| WHERE | どこで変更するか | **どの概念空間が疎か**(暗黒物質) | 233スクリプト中67.0%が未カバー(82.4%→67.0%改善)。到達不能=先行知識なし |
| WHO | 誰が影響を受けるか | **誰が書き、誰が読むか** | 書込65本(軍25+家35+忍4+将1)。消費=忍者+将軍のみ。家老/軍師が読まない |
| HOW | どうやって実現するか | **密度と到達性をどう保証するか** | 辺の自動生成あり(origin BLOCK)。概念追加はD0手動=意志依存(Phase 4) |
