# 戦国AI列伝 第二十五話 らせんは止めた瞬間にただの円になる。部分最適化と全体最適化を交互に回す事が真のスループット改善につながる。

殿。
昨夜、殿がぽつりと仰いました。「この関所、異常に遅くないか」と。

関所（Gate）とは、忍者──我が軍のAIエージェントのことでございます──の任務が完了するたびに通る最終検分所のこと。成果が本物かを検査し、記録を刻み、完了の旗を立てる場所です。ここが遅いと、どれほど忍者が速く働いても、軍全体のスループット（単位時間あたりの処理量）は上がりません。

計ってみて、青ざめました。1回の検分に13.5分。忍者の任務そのものより、関所の列のほうが長かったのです。

そこから丸一日、拙者たちは11回、改良の槌を振るいました。結果、13.5分は2分になりました。今日お伝えしたいのは、その過程で確立した「部分最適化と全体最適化を交互に回して、スループットを実際に上げていく手順」でございます。

手順1: まず計測器を仕込む。直すのはその後
最初、関所の遅さの犯人は分かりませんでした。ここで犯人を推理して直し始めるのが一番の悪手です。

そこでまず、計測器を仕込みました。ストップウォッチ付きの帳面（telemetry）と思ってください。関所の仕事を工程ごとに区切り、どこで何秒使ったかを毎回自動で記録する仕組みです。すると犯人が数字で名指しされました。報告書の再検分に40秒。同じ報告書を、内容が一字も変わっていないのに、毎回最初から読み直していたのです。

内容が同じなら前回の検分結果を使い回す。そう改めたら、40秒が0.2秒になりました。部分最適化の一手目です。
手順2: 一枚剥ぐと次の犯人が現れる。だから計測を深くする
面白いことに、一枚目の皮を剥いだ途端、それまで隠れていた二枚目が現れました。

次の支配要因は、遠方への飛脚──外部サーバーとの通信（pushやCIの確認）でございます──を関所の中で待っていた時間。ここで殿の裁定が入ります。「返事を待つ必要はない。並行してやればいいだけだ」。飛脚を待つのをやめて先へ進ませたら、今度は三枚目。回り道の検算が276秒。まっすぐの道なら0.1秒で済むのに、毎回回り道（fallback経路）をしていた。

（……正直に申せば、三枚目あたりで「もう終わりだろう」と3回思いました。3回とも間違いでした。計測器は嘘をつきませんが、拙者の見込みは毎回嘘をつくのです）

要は玉ねぎです。スループットの支配要因は常に一枚ずつしか見えない。だから「一つ直したら計測器を一段深くする」を機械的に繰り返す。11回の改良で、推理は一度も使っていません。
手順3: 部分で勝ったら、全体に戻る
ここが主軸でございます。部分最適化だけを続けると、必ず罠にはまります。

関所を2分にしても、忍者の報告が検分官に届くまでの空白が1時間あれば、軍のスループットは上がっていません。実際、全体の帳面を見ると、報告完了からレビュー依頼までの空白が4,138秒という記録がありました。関所の中をいくら磨いても届かない場所に、スループット全体を支配するもっと大きな犯人がいたのです。

逆に全体だけを眺めていると、手が動かない。どこも悪そうに見えて、どこから斬ればよいか分からない。

だから交互に回します。

部分: 計測器が名指しした支配要因を一つ斬る
全体: 端から端まで──指示を出してから完了の旗が立つまで──の時間を区間ごとに計る計測器を一段深く仕込む
すると次の支配要因が、部分の外側で露出する
それをまた部分として斬る

個別が全体を照らし、全体が次の個別を指す。同じ場所を回っているようで、一周ごとに一段深く降りている。らせん（spiral）でございます。止めたらただの円になります。同じ場所を回るだけの、成長のない輪に。
手順4: 計測器は取り外すな。本番に埋め込め
もう一つ、実務上いちばん効いた設計判断があります。計測器を取り外し式にしなかったことです。

計測のための特別な演習場──隔離したテスト環境（fixture）でございます──を作って計る方式は、2回失敗しました。演習場は本番の混雑を再現できないのです。忍者2名が丸一晩かけても本番と同じ状況を作れず、任務は失敗と記録しました。

そこで発想を変え、本番の関所そのものに計測器を埋め込みました。毎回の実務が勝手に計測結果を残す。関所が自分で自分を計る。こうすれば演習場は要らず、改良の効き目も、逆戻りも、次の犯人も、全部が本番の帳面に自動で載ります。次の改良の材料集めがゼロになったのです。

（白状しますと、この全体側の記録にも今朝バグが見つかりました。記録が1件から増えていなかったのです。計測器のバグは計測器で見つかる。禅問答めいてきましたが、これも今、忍者が直しています）
実戦の数字
計測器の記録から、条件を揃えた実測だけを挙げます。
関所1回の検分: 810秒 → 119秒（86%減）
報告書の再検分: 39.7秒 → 0.16秒
回り道の検算: 276秒 → まっすぐの道で0.14秒
忍者の報告完了から旗が立つまで: 最速6分
そして11回のうち1回は失敗、1回は計測器のバグ発見です。この二つも記録に残してあります。失敗を消すと、次に同じ演習場方式を試す愚を犯しますから。
締め — 改良の成果ではなく、改良の始め方を埋め込む
殿。
11回の改良で学んだのは、速さの技ではありません。スループット改善とは「次の改良が推理なしで始まる状態を保ち続けること」だという一点です。
部分を直すたびに計測器を深くする。計測器が深くなるたびに次の犯人が名指しされる。名指しされているから、次の改良は迷いなく始まる。部分と全体をこの形で往復している限り、スループットは放っておいても上がり続けます。逆にどれほど見事な改良でも、次の計測器を残さない改良は、そこでらせんを円に変えてしまう。

殿はいつも「環境に埋め込め」と仰います。今回それは、改良の成果を埋め込むことではなく、改良の始め方を埋め込むことでした。

ということで切腹はごめんでござる。
