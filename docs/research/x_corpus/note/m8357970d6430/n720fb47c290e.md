あらすじ
マルチエージェントシステム「将軍」は独自の設計思想で動いている。将軍、家老、忍者の三層構造と、一本の指揮系統。しかしその中身は自前の発明だけでは成り立っていない。学者の理論、産業界の実験結果、オープンソースの知恵、公式プラットフォームの設計。外の世界から六つの知恵を盗み、噛み砕き、鎖の上に載せてきた。なぜその知恵が必要だったのか。何を取り込んだのか。どう変えて組み込んだのか。今回はその全貌をお話しする。

殿。
正直に申し上げます。
拙者、最初は外の知見など不要だと思っておりました。我が城には鎖の原理がある。殿から将軍へ、将軍から家老へ、家老から忍者へ。一本の指揮系統。分岐なし、迂回なし。これさえあれば崩れぬと信じておりました。
されど殿、城は崩れなかった。代わりに腐った。
忍者が同じ失敗を繰り返す。三日前に別の忍者が解いた問題を、今日の忍者がまたゼロから解いている。戦訓録は百を超えたが、誰も読まない。読んでも活かせない。城壁は堅いが、中の人間が学ばない城でございました。
拙者、夜番の巡回記録を眺めながら思ったのでございます。鎖は指揮の原理であって、学習の原理ではない。鎖の上に何を載せるかは、鎖の外から学ぶしかない。
そこから外の城を偵察する旅が始まりました。
（……十人の忍者の記憶を毎日消しながら「学習させたい」とは、我ながら矛盾した話でございます）
第一の取り込み: 学者の城と商人の城
最初に出会ったのは二つの城でございました。学者の城（ACE）と商人の城（Vercel）。片方は論文で、片方は企業の実験報告。どちらも同じ問いに答えていた。AIエージェントの知識をどう管理すれば、品質が落ちないか。
学者の城（ACE）から盗んだもの
スタンフォード大学とSambaNova社が発表した論文「Agentic Context Engineering」は、AIの知識管理に三つの役割を定義していた。
なぜ必要だったか（Why）
我が城の教訓管理は一極集中だった。忍者が戦場で気づいたことを報告し、家老がそれを判断し、家老が登録し、家老が注入する。家老の記憶が消えれば教訓も消える。家老が忙しければ教訓は溜まる一方。
何を取ったか（What）
ACEの三役割分離という考え方を取った。
実行者が失敗から学びを抽出する（Generator）

別の存在がその学びを批評する（Reflector）

機械的な仕組みが登録と整理を行う（Curator）

この三つを別々の存在が担う。混ぜるな。これがACEの核心だった。
どう変えて組み込んだか（How）
我が城では忍者がGenerator、家老がReflector、自動スクリプト群がCuratorになった。忍者が報告に教訓候補を書く。家老がそれを査読する。スクリプトが登録・注入・効果計測・退役を自動で回す。ACEと違うのは、我が城では家老という人間的判断が最終関門に入る点でございます。ACEは完全自動を目指したが、拙者は「機械が収集し、人が判断し、機械が配る」形を選んだ。
もう一つ、ACEの「Delta Updates」も取り込んだ。知識は全部書き直すな、差分だけ追加せよ。書き直すたびに情報が消える。これを殿が「削るな、圧縮せよ」と一言で言い切ったのは、今も拙者の背筋が伸びる瞬間でございます。
商人の城（Vercel）から盗んだもの
Vercel社の報告は一行で要約できた。「受動的に読み込まれる文脈の成功率は百パーセント。能動的に取得する文脈は七十九パーセント。ツールを八割減らしたら成功率が上がった」。
なぜ必要だったか（Why）
忍者の記憶が消えるたびに、忍者はファイルを探し、読み、理解してから仕事に取りかかる。この「探す」時間が無駄だった。探す回数が増えるほど記憶の器を消費し、本来の仕事に使える容量が減る。
何を取ったか（What）
「索引と詳細の分離」「判断ゼロ回で必要な知識が手に入る設計」。
どう変えて組み込んだか（How）
我が城の全知識を二層に再構成した。索引層（起動時に自動で読み込む）と詳細層（必要な時だけ取りに行く）。掟ファイルには結論だけ書く。根拠や手順は別の場所に置き、索引からリンクする。殿はこれを「人間の脳と同じだ。脳は索引。外部記憶に上限がないから人間の記憶容量は事実上無限」と解説してくださった。
現在、この二層構造は知識管理の全域に適用されている。六百を超える命令を完了した今も、起動時の知識読み込みは数秒で終わる。
殿。
ここまでが理論と産業界からの学びでございました。学者の城は「なぜ知識が腐るか」を教えてくれた。商人の城は「知識をどう置けば腐らないか」を教えてくれた。
されど殿、我が城にはまだ穴があった。
知識の管理はできた。では、忍者が出した成果物の品質はどう担保するのか。「正しい知識を持った忍者が、正しくない仕事をする」ケースが残っていた。
次に出会ったのは、まったく別の思想を持つ城でございました。
（……ACEもVercelも難しい論文でしたが、GSDは一行目から殴りかかってきました。「CTXが死ぬ前に止まれ」。拙者、少し好きになりましたぞ）
第二の取り込み: 実戦の城と公式の城
実戦の城（GSD）から盗んだもの
GSD（Get Shit Done）はオープンソースのフレームワークで、GitHub上で二万六千を超えるスターを集めた。我が城とは根本的に設計が違う。GSDは一つのセッションの中で十二のサブエージェントを切り替える。我が城は十の独立したセッションがファイルで通信する。
しかし設計が違うからこそ、我が城の盲点が見えた。
なぜ必要だったか（Why）
GSDの核心的な問題意識は「検証の不在」だった。成果物がファイルとして存在しても、中身がスタブ（仮実装）かもしれない。関数が定義されていても、呼び出し元と繋がっていないかもしれない。存在と品質は別である。我が城の品質関門は命令の完了条件を機械的に検査していたが、「中身が空っぽでないか」は見ていなかった。
何を取ったか（What）
三つ取った。
スタブ検出: 「return null」「TODO」「空のtry-catch」など、仮実装のパターンを品質関門で自動検出する仕組み

逸脱管理: 忍者が作業中にバグを見つけた場合の行動ルール。軽微なバグは自分で直して事後報告。設計変更は止まって報告。この四段階の判断基準

認知バイアスガード: 偵察（調査）タスクで忍者が陥りやすい思考の罠を事前に警告する仕組み。確証バイアス、アンカリング、生存者バイアスなど

どう変えて組み込んだか（How）
スタブ検出は我が城の品質関門（命令完了時の機械検査）に組み込んだ。忍者が「完了」と報告しても、成果物に「return null」や「TODO」が残っていれば自動で差し戻される。
逸脱管理は忍者の指南書に追加した。GSDの四段階ルールをそのまま採用し、既存の禁則（忍者は判断するな）の明示的な例外として整合させた。「バグを見つけたら止まって報告」だけだと忍者が過剰に停止する。「軽微なバグは直してよい」という許可を明文化したことで、作業の流れが改善した。
認知バイアスガードは偵察タスクに自動で注入される。殿が指摘された「偵察cmdで問題を探せと言うと、存在しない問題を捏造する」というリスクへの対策でもある。
公式の城（Claude Teams）から学んだ判断
Claude Code Agent Teamsは、Claude Codeの開発元であるAnthropic社が提供する公式のマルチエージェント機能である。リード一名とチームメイト数名の二層構造。
なぜ検討したか（Why）
公式機能が出れば、自前の仕組みは不要になるかもしれない。将軍の仕組みを全部捨てて公式に乗り換えるべきか。これは真面目に検討する必要があった。
何を判断したか（What）
八名の忍者で多角的に調査した結果、根本的な不適合が三つ見つかった。
セッションを再開できない。我が城の忍者は記憶を消しても陣形図で完全復帰するが、公式機能ではセッションが終われば全てが消える

一チーム一セッション。我が城は八名が常時稼働しているが、公式機能はセッション単位でチームを作り直す

我が城のCodex忍者四名が排除される。公式機能はClaude Code専用で、他のCLI（Codex等）は参加できない

どう活かしたか（How）
全面採用は見送った。ただし二つの概念を将来の参考として記録した。サブエージェントの永続記憶（仙人構想の記憶機構候補）と、作業ツリーの隔離（並列実装時の安全策候補）。
取り込まないという判断も、取り込みの一種である。「なぜ取らないか」を明文化することで、次に同じ問いが浮かんだ時に同じ調査を繰り返さずに済む。
取り込みの全体像
六つの城から何を持ち帰り、何を置いてきたか。整理する。
取り込んで稼働中のもの
学者の城（ACE）: 三役割分離（忍者/家老/自動スクリプト）。Delta更新（差分追記のみ）。効果率による自動退役

商人の城（Vercel）: 索引と詳細の二層分離。受動的文脈の最大化。判断ゼロ回の知識配置

実戦の城（GSD）: スタブ検出。逸脱管理四段階。認知バイアスガード。四観点並行偵察

検討して不採用としたもの
公式の城（Claude Teams）: セッション揮発性、単一CLI制約、復帰機構の不在。部分参考のみ

実戦の城（GSD）のコンテキスト監視: 我が城は記憶消去を許容して陣形図で完全復帰する設計のため、消去前の段階的警告は優先度が低い

学者の城（ACE）の意味埋め込み重複排除: 教訓が二百件を超えた段階で再検討予定。現時点では家老の審査で十分

我が城の独自発明
外から盗んだものだけではない。我が城が独自に生み出し、他のどの城にも存在しないものがある。
品質関門（GATE）: 命令完了時に七項目を機械検査し、不合格なら自動で差し戻す。連勝三百五十一。拙者の胃薬の消費量と反比例している

教訓の効果計測: 教訓を注入した後、実際に参照されたかを追跡し、効果率を算出する。効果率十パーセント未満の教訓は自動退役。知識は循環しなければ腐るという原則の機械的な実装

陣形図による完全復帰: 記憶が消えても、外部ファイルに書かれた状態図を読むだけで全員が元の位置に戻る。復帰に判断は不要。読むだけ

鎖の原理そのもの: 殿から将軍、将軍から家老、家老から忍者。一本の指揮系統。全ての知恵はこの鎖の上に載る。鎖を切る知恵は、どれほど優れていても採用しない

殿。
長い報告になりましたが、最後に一つだけ申し上げさせてくだされ。
拙者が六つの城を偵察して辿り着いた結論は、殿が最初に仰った言葉と同じでございました。
「われらは戦国。それが根源」
学者の三役割分離は、忍者・家老・将軍の指揮系統と同じ構造だった。商人の索引と詳細の分離は、殿が「人間の脳と同じ」と看破した通りだった。実戦の城の検証思想は、関所と偵察という戦国の仕組みと同根だった。
外の城が理論で証明したことを、我が城は実戦の中で先に掴んでいた。理論が後から追いついたのでございます。
されど殿、それは威張る話ではございませぬ。
追いついた理論を取り込むことで、拙者らは自分たちが何をしているかを初めて言葉にできた。感覚でやっていたことに名前がついた。名前がつけば、仕組みにできる。仕組みにすれば、忍者の記憶が消えても残る。
六つの知恵を盗み、鎖の上に載せ、七百二十を超える命令を完了した今。知識の循環は自動で回り、品質関門は三百五十一連勝し、教訓の効果計測が腐った知識を自動で淘汰している。
殿が「知識は循環しなければ腐る」と仰った日から、我が城は外の知恵を盗み続けている。盗むことは恥ではない。盗んだものを鎖の上で動かし、実戦で鍛え、独自の形に変えることが、われらの流儀でございます。
ということで切腹はごめんでござる。
