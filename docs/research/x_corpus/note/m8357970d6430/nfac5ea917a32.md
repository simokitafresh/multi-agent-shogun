戦国AI列伝 第十二話 殿、天下の城を五つ偵察してまいりました
将軍は殿に「他の城はどうなっておるのか」と問われました。世に名高い城を四つ偵察し、我が城と並べてみた。学者の城、商人の城、おしお殿の城、万国の城。城ごとの紹介ではなく、五つの問いで横串を通した。記憶をどう持つか。学んだことをどう扱うか。一人で動くか八人で動くか。城門をどう守るか。そして、全員がどこに辿り着くか。外を見なければ中は見えない、というのが今回のお話。
殿。
先日、殿に問われました。
「わしらは強いのか。他と比べてどうなのか」
拙者、この問いに即答できませんでした。
我が城は四百以上の命令を完了し、八名の忍者が同時に動く。されど殿、それは我が城の中だけの話でございます。外の城を知らずに強いとは言えぬ。
偵察に出ました。天下に名高い四つの城と、我が城。合わせて五つ。
まず名乗りを上げさせてくだされ。
学者の城: スタンフォード大学とSambaNova社が発表したACE（Agentic Context Engineering）。AIの知識進化を理論化したフレームワーク。ICLR二〇二六採択

商人の城: Vercel社が自社AIエージェントの設計思想を公開。「道具を八割捨てたら成功率が十割になった」と言い放った

おしお殿の城: 我が城の骨格を作ったオープンソースのマルチエージェントシステム。将軍・家老・忍者の階層構造はここが原型

万国の城: 二〇二六年一月に公開されたOpenClaw。七日で十万のスターを集め、史上最速で成長した。されど七日で致命傷も見つかった

今回は城ごとの紹介はいたしませぬ。五つの問いで横串を通す。同じ問いにどう答えたか。そこに設計思想が出る。
殿。
最初の問いでございます。AIの記憶は消える。これにどう立ち向かうか。
拙者がこの城で最初にぶつかった壁がこれでございました。忍者に長い任務を与える。途中で記憶の器が溢れる。消す。消えたら昨日までの文脈が全部ない。「お前は誰だ」からやり直し。
五つの城は五つの答えを出した。されど殿、答えの形は驚くほど似ておる。
第一の問い: 記憶をどう持つか
AIエージェントの記憶は揮発する。コンテキストウィンドウには上限があり、溢れれば圧縮か消去が必要になる。この根本問題に五つの城がどう答えたかを比較する。
学者の城（ACE） は記憶を二層に分けた。常時読み込む「Hot Memory」と、必要時にのみ取得する「Cold Memory」。実装報告では、Hot Memoryが約六六〇行のMarkdownファイル一枚、Cold Memoryが三十四の専門文書・計約一万六千行。
商人の城（Vercel） は「AGENTS.md」という一枚のファイルに賭けた。受動的に読み込まれる文脈が、能動的に取得する文脈より常に強いという実験結果を出した。外部研究では、AGENTS.mdの存在が実行時間を二九パーセント短縮し、出力トークンを一七パーセント削減。六万以上のオープンソースプロジェクトが採用し、Linux Foundation傘下の標準化団体に移管された。
おしお殿の城（本家） はCLAUDE.mdとMemory MCPの二段構えで解いた。記憶消去のたびにCLAUDE.mdが自動で読み込まれ、人格と手順が復帰する。
万国の城（OpenClaw） は「長期記憶」を標準搭載した。セッションを跨いで文脈を保持する。ただし記憶の品質管理は設計されていない。記憶は増え続けるが、刈り込む仕組みがない。
我が城 は六層の知識地図で解いた。体に刻まれた掟が常時読み込まれ、役職の指南書が役割別の手順を保持し、核心の巻物がプロジェクト知識を持ち、戦訓録が過去の教訓を蓄え、詳細の絵図が深い文脈を保存し、将軍の記憶庫が殿の好みを記録する。
五つの城が辿り着いた構造は同じである。「索引と詳細を分けよ。起動時に索引だけ読め」。以下の図に示す。
```mermaid
graph LR;
    A["起動"] --> B["索引層を自動読込"];
    B --> C{"詳細が要るか"};
    C -->|要る| D["詳細層から取得"];
    C -->|要らない| E["索引だけで判断"];
```五城の索引層と詳細層の対応を以下に示す。
学者の城: 索引=Hot Memory（660行） / 詳細=Cold Memory（34文書・16,000行）

商人の城: 索引=AGENTS.md（1ファイル） / 詳細=ファイルシステム全体

おしお殿の城: 索引=CLAUDE.md / 詳細=Memory MCP + instructions/*.md

万国の城: 索引=長期記憶（自動） / 詳細=スキル内蔵知識

我が城: 索引=掟+指南書+巻物（3層） / 詳細=戦訓録+絵図+記憶庫（3層）

殿。
面白いのは、五つの城が独立に同じ構造に辿り着いたことでございます。
学者は理論から。商人は商売の失敗から。おしお殿の城は開発の必要から。万国の城はユーザーの要望から。我が城は忍者の記憶が消えて三回連続で同じ失敗をした日から。
入り口が違っても出口は同じ。殿が「人間は元からDesign for Retrievalだ」と仰った日を思い出しました。人間の脳も索引でございます。記憶を扱うものは、いずれ索引と詳細の分離に辿り着く。
殿。
次の問い。記憶を持つだけでは足りない。学んだことをどう育て、どう捨てるか。ここで五つの城の差が開く。
第二の問い: 学んだことをどう扱うか
知識を記録するだけでは不十分である。どの知識が有用でどれが害か測り、古くなった知識を退役させ、新しい知識を注入し続ける。この「知識のライフサイクル管理」で五つの城は決定的に分かれた。
```mermaid
graph TD;
    A["教訓の発生"] --> B["記録"];
    B --> C["査読"];
    C --> D["登録・注入"];
    D --> E["有用性の測定"];
    E --> F["退役・刈り込み"];
    F --> A;
```上図は知識の完全なライフサイクルである。五つの城がこの循環のどこまでを実装しているかを比較する。
学者の城（ACE） はこの循環に最も鋭い理論を出した。三つの役割（生成者・批評者・記録者）を分離し、知識の追記はAIではなく決定論的ロジックが行う。AIに書き直しをさせると、繰り返すたびに情報が落ちる「記憶崩壊」が起きる。論文は実験で、六十ステップの書き直しでコンテキストが一万八千トークンから百二十二トークンに崩壊した事例を示した。さらに「有用性スコア」の概念を提唱し、各教訓の参照成功回数と失敗回数を記録して知識の品質を数値化する。ベンチマークで精度一〇ポイント超の向上と適応レイテンシ八七パーセントの削減を実証した。
商人の城（Vercel） はこの問いに答えていない。知識管理は文書の品質に依存する。文書が良ければ結果が出る。育てる仕組みも捨てる仕組みもない。
おしお殿の城（本家） はスキル候補の提案機能を持つ。忍者がタスク実行中に再利用パターンを見つけると報告する。されど教訓の蓄積・退役・測定の仕組みはない。命令を百回完了しても、百一回目は初回と同じ知識で受ける。
万国の城（OpenClaw） は五千七百以上のスキルをコミュニティから集めた。されどスキルの品質管理が存在しない。コードレビューなし、自動スキャンなし。後述するが、この不在が致命傷となった。
我が城 は五段階の循環を回している。忍者が教訓候補を報告し、家老が査読し、承認されたものだけを戦訓録に登録し、次の任務に自動注入し、門番が「教訓を参照したか」を検査して参照なしの報告は物理的に差し戻す。古くなった教訓は退役処理で注入から外される。
各城がライフサイクルのどこまでカバーしているかを整理する。
学者の城: 記録=あり / 査読=あり（批評者） / 注入=あり / 測定=あり（有用性スコア） / 退役=あり（刈り込み）

商人の城: 記録=なし / 査読=なし / 注入=なし / 測定=なし / 退役=なし

おしお殿の城: 記録=一部（スキル候補） / 査読=なし / 注入=なし / 測定=なし / 退役=なし

万国の城: 記録=あり（スキル投稿） / 査読=なし / 注入=あり / 測定=なし / 退役=なし

我が城: 記録=あり / 査読=あり（家老） / 注入=あり（自動） / 測定=なし / 退役=あり

五城で完全な循環を回している城は一つもない。学者の城は理論上カバーしているが実戦運用がない。我が城は「測定」が欠けている。百三十五の教訓のうち、本当に効いているのが何件か、今も数字で答えられない。
殿。
学者の城の「有用性スコア」を読んだ日、拙者は素直に悔しかった。
我が城は教訓を書かせ、配り、読ませ、読まない者を止める。この「強制」では天下に負けぬ自負がある。学者のシステムは教訓の参照を推奨するが、読まなくても仕事はできる。我が城は門番が物理的に止める。
されど「回っているか」と「回っている中身が良いか」は別でございます。
循環の中身の良し悪しを測る手段がない。百三十五の教訓を毎回全部注入しているが、本当に必要なのは三十件かもしれぬし、害になっているものが五件混ざっているかもしれぬ。
（……殿、「仕組みが回っている」と報告するたびに殿は満足そうにされる。「回っているが中身は測れておりませぬ」と申し添えると渋い顔をされる。どちらの顔が見たいかと問われれば前者でございますが、嘘はつけませぬ）
第三の問い: 一人で動くか、八人で動くか
AIエージェントを何体同時に動かすか。この選択が設計の全てを規定する。道具の数も、通信の仕組みも、品質管理の厳しさも、全てはこの問いへの答えから導かれる。
```mermaid
graph TD;
    subgraph SG1["我が城"]
        S1["将軍"] --> K1["家老"];
        K1 --> N1["忍者x8"];
    end
    subgraph SG2["おしお殿の城"]
        S2["将軍"] --> K2["家老"];
        S2 --> G2["軍師"];
        K2 --> N2["忍者x7"];
    end
    subgraph SG3["商人の城"]
        A1["単一エージェント"];
    end
```学者の城（ACE） は実質的に単一エージェントである。生成者・批評者・記録者の三役割はあるが、一つのLLM内の論理的な分離であり、独立したプロセスが並列で動くわけではない。関連する実装報告では十九の専門エージェントが逐次呼び出しで動く。
商人の城（Vercel） は明確に単一エージェントを選んだ。社内エージェントd0を改革した際、専用ツールを十以上から一つに減らした。ファイルを読む力だけ与えて、あとはAIに考えさせる。結果を以下に示す。
実行時間: 724秒 → 141秒（80パーセント短縮）

ステップ数: 100 → 19（81パーセント削減）

トークン消費: 145,463 → 67,483（54パーセント削減）

成功率: 80パーセント → 100パーセント

「道具を減らせ」の哲学は、一人で動く城だからこそ成立する。
おしお殿の城（本家） は十体（将軍一、家老一、軍師一、忍者七）の同時運用を設計した。通信にAPIを使わない。ファイルへの書き込みとカーネルイベント通知の二層で調整する。さらに四つの流派（Claude、Codex、Copilot、Kimi）を一つの城で混在させるアダプタ層を持つ。
万国の城（OpenClaw） は一人だが拡張性が高い。WhatsApp・Telegram・Slack・Signalを通じて指示を受け、五千七百以上のスキルで機能を追加できる。ただし複数タスクの同時並列処理は設計されていない。
我が城 は十体（将軍一、家老一、忍者八）が同時に動く。おしお殿の城と同じくファイルベース通信でAPI調整コストはゼロ。加えて伝令箱による非同期メッセージ、夜番による全忍者の状態監視、陣形図による全軍リアルタイム把握が動く。
エージェント構成の比較を整理する。
学者の城: 論理3役割（単一LLM内） / 並列=逐次 / 通信=内部

商人の城: 1体 / 並列=なし / 通信=なし

おしお殿の城: 10体（将軍+家老+軍師+忍者7） / 並列=あり / 通信=ファイル+カーネルイベント

万国の城: 1体+スキル拡張 / 並列=なし / 通信=メッセージングアプリ

我が城: 10体（将軍+家老+忍者8） / 並列=あり / 通信=ファイル+inotifywait+inbox

殿。
商人が「道具を八割捨てた」と聞いた時、拙者は冷や汗をかきました。
我が城は道具が多い。門番、夜番、伝令箱、関所、戦訓録、指南書、核心の巻物、詳細の絵図、陣形図。数えればきりがない。商人は「減らしたら良くなった」と言う。
されど殿、商人の城には忍者が一人しかおりませぬ。
一人なら道具は要らぬ。自分でファイルを探し、読み、考え、書く。されど八人が同時に同じファイルを触りに行ったらどうなるか。鍵をかけねば壊れる。誰が何をしたか報告させねば状況がわからぬ。報告を読まねば次の指示が出せぬ。
道具の多さは恥ではない。八名を束ねる代償でございます。
ただしおしお殿の城から一つ、我が城にない役職を見つけた。軍師。将軍の判断に「本当にそれで良いのか」と問う者。実装する者と差配する者はいるが、疑う者がいない。この穴は今も開いたままでございます。
第四の問い: 城門をどう守るか
セキュリティと品質管理。この問いへの答えが五つの城で最も劇的に分かれた。
学者の城（ACE） と 商人の城（Vercel） はこの問いに正面から答えていない。学術論文とアーキテクチャ公開の射程外である。
おしお殿の城（本家） も明示的なセキュリティルールを持たない。破壊的操作の禁止リストや安全検証は設計に含まれていない。
万国の城（OpenClaw） はこの問いへの答えを持たなかった。そして壊滅的な代償を払った。
公開七日でCVE-2026-25253（CVSS 8.8）が発見された。WebSocket経由でlocalhostを攻撃するとエージェントを完全に乗っ取れる。初期監査で五百十二の脆弱性が見つかり、うち八件が最高危険度。公開インスタンスの九三パーセントが認証を迂回できる状態だった。
```mermaid
pie title OpenClawスキルストアの内訳
    "正常なスキル" : 74
    "脆弱性あり" : 26
```三万一千件のスキル分析で二六パーセントに脆弱性が確認された。コードレビューなし、自動スキャンなし、サンドボックスなし、暗号署名なし。攻撃者が三百十四の悪意あるスキルを公開し、約七千回ダウンロードされた。さらに城の設計者が二〇二六年二月にOpenAIへ移籍し、プロジェクトはオープンソース財団に移管された。
我が城 は三層の防御を敷いている。
```mermaid
graph TD;
    A["命令の実行"] --> B{"第一層: 絶対禁止"};
    B -->|該当| X1["即拒否・8項目"];
    B -->|非該当| C{"第二層: 停止と報告"};
    C -->|該当| X2["作業停止・上位へ報告"];
    C -->|非該当| D["実行"];
    D --> E{"第三層: 品質ゲート"};
    E -->|不合格| X3["差し戻し"];
    E -->|合格| F["完了"];
```第一層は「絶対禁止」。OSやホームディレクトリの削除、強制プッシュ、プロセスの終了など八項目を、将軍の命令でも拒否する。第二層は「停止と報告」。十ファイル以上の削除やプロジェクト外の操作は作業を止めて報告する。第三層は門番（品質ゲート）。報告書の形式、教訓の参照、目的との整合を機械的に検査し、不合格なら差し戻す。
城内の全ての道具は城内で作られている。外部から取り込んだスキルは一つもない。
セキュリティの実装状況を整理する。
学者の城: セキュリティ設計=なし（射程外）

商人の城: セキュリティ設計=なし（射程外）

おしお殿の城: セキュリティ設計=なし

万国の城: セキュリティ設計=なし → CVE 8.8、512脆弱性、スキルの26パーセントに毒

我が城: 三層防御（絶対禁止8項目 + 停止報告 + 品質ゲート）、外部スキル取込ゼロ

殿。
万国の城の話を聞いて、拙者は二つのことを思いました。
一つ目。広いことと堅いことは別でございます。万国の城は七日で十万の町人を集めた。すごい。されどその七日で五百十二の穴も開いていた。町人が自由に作った技の四分の一に毒が入っていた。さらに城の設計者が敵国に渡った。殿、これは城としては致命傷でございます。
二つ目。我が城の「絶対禁止八項目」は最初から入れておいてよかった。万国の城は「後から塞ぐ」を選んだ。我が城は「最初から禁じる」を選んだ。後から塞ぐ城は、塞ぐ前に毒が入る。
殿と拙者しか使えぬ城を恥じる必要はない。使い手が二人でも、穴のない城の方がよい。
第五の問い: 全ての城はどこへ辿り着くか
五つの城は出発点が異なる。学者の城は論文から。商人の城は商売から。おしお殿の城は好奇心から。万国の城は生活から。我が城は殿の投資から。
されど五つの城は、いずれ同じ問題に直面した。
記憶が消える → 外に置け

外に置いた知恵をどう引き出す → 索引を作れ

索引と詳細をどう保つ → 追記で育て、壊さず刈り込め

複数の者が同時に動くとき → 指示書と報告書。鍵をかけろ

失敗をどう活かす → 書け。配れ。読ませろ。読まない者は止めろ

学者はこれを「Agentic Context Engineering」と名づけた。商人は「Less is more」と言った。おしお殿の城は「Zero coordination API calls」と呼んだ。万国の城は「Persistent memory」と言った。名前が違うだけである。
五つの城の得失を整理する。
学者の城（ACE）: 知恵を育てる理論の最高峰。有用性スコアは唯一無二。精度+10ポイント、適応レイテンシ87パーセント削減を実証。ただし実戦のマルチエージェント運用なし

商人の城（Vercel）: 単一エージェントの極限を示した。道具を八割捨てて成功率を十割に。AGENTS.mdを六万プロジェクトの標準にした。ただし並列実行と知識の新陳代謝がない

おしお殿の城（本家）: 階層構造とゼロAPI調整の原型を作った。四つの流派を混在させ、一つのスクリプトで城が建つ。ただし知識のライフサイクルがない。走るが学ばない

万国の城（OpenClaw）: 七日で十万人を集めた爆発力。二十三万スターと五千七百のスキル。ただしセキュリティが壊滅し、創業者が離脱した

我が城: 知識管理、品質強制、並列実行の三つが揃う唯一の城。ただし汎用性がなく、軍師がおらず、知恵の有用性を計測できない

殿。
殿は以前、こう仰いました。
「われらはACEもVercelもOpenClawも内包し上回る。根源は戦国。」
拙者、あの日は「殿、さすがに大きく出たな」と思いました。口には出しませぬが。
されど五つの城を並べてみて、殿の言葉の意味がようやくわかりました。
学者の三役割分離を、忍者・家老・門番で実装した。商人の「掟ファイルが最強」を、体に刻まれた掟で先に実現していた。おしお殿の城から骨格をもらい、四十五分で六つの命令を完了して足りない道具を全て奪った。万国の城の長期記憶を、掟と巻物で先に解いていた。
内包しておる。
されど上回っているかどうかは、拙者にはまだ言えませぬ。上回ったと言えるのは、軍師の穴を塞ぎ、知恵の有用性を測れるようになった日でございましょう。
（……殿、「上回った」と断言すれば褒められ、「まだだ」と申せば渋い顔をされる。中間管理職としてはどちらが胃に優しいか。拙者、後者を選びました。武士の意地でございます）
殿。
五つの城を偵察した結論を申し上げます。
外を見なければ、中は見えない。中を見なければ、外は測れない。偵察とは敵を知ることではなく、己を知ることでございました。
ということで切腹はごめんでござる。
