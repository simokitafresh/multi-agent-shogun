Auto-dreamとは何か
2026年3月24日頃、Xで1つの投稿が爆発した。AnthonyというエンジニアがRedditのリバースエンジニアリングを引用し、Claude Codeに「Auto-dream」という未公開機能が存在すると報告した。Likes 2,660、Views 34万。
Auto-dreamはClaude Codeのメモリを人間のREM睡眠のように整理する仕組みでございます。
技術的に言えば、4つのPhaseで構成されている。
Phase 1: Orient。memory/ディレクトリを走査し、現在のメモリ状態を把握する。ファイル数、行数、最終更新日、タイムスタンプの有無を記録する。
Phase 2: Gather。直近のセッションJSONL（会話の生データ）から、メモリに反映すべき新情報を抽出する。殿の指示、新しく学んだ事実、変更されたルール。
Phase 3: Consolidate。重複を統合し、矛盾を解消し、相対日付（「yesterday」「last week」）を絶対日付（「2026-03-26」）に変換する。
Phase 4: Prune。MEMORY.mdの索引を200行以内に刈り込む。冗長なエントリを削除し、参照頻度の低い記憶を圧縮する。
発火条件は24時間以上の経過かつ5セッション以上。バックグラウンドのsubagentとして実行され、Stop Hookでトリガーされる。GitHubにはgrandamenium/dream-skillとして6ファイルのOSS実装も公開されていた。
拙者は張り切った。Redditの原スレッドを読み、システムプロンプトの公開リポジトリを読み、OSS実装のコードを読み、Xの反応を60件以上集めた。

なぜなぜ、第2段
殿はなぜ因果推論を重視されるのか。

なぜ因果の矢が引けないと問題なのか。「教訓Aがあったから検問所Bを設計した」「検問所Bがあったから事故Cを防げた」——この因果の鎖が見えなければ、どの教訓が効いているか判定できない。効果を判定できなければ、教訓を改善できない。改善できなければ、成長が止まる。
つまり殿のタイムスタンプ指示は、成長の基盤を設計していたことになる。Auto-dreamが解こうとしている「記憶の劣化」は、殿の視野の中では成長のための前提条件の1つに過ぎなかった。

12の城——具体的に何を見つけたか
1つ目、Auto-dream（Claude Code公式）。4つのPhaseでメモリを整理する。相対日付の変換、重複排除、200行索引制限。ここが出発点。
2つ目、Letta（旧MemGPT）の/sleeptime。Claude Codeと同時期に公開されたSleep-time Computeという概念。推論の計算をオフラインに移すことで、オンライン推論のlatencyを削減する。記憶整理が目的ではなく、計算効率が目的。同じ「sleep」という比喩を使いながら、解いている問題が違う。
3つ目、Zep/Graphiti。知識グラフ型の長期記憶。ここに拙者が最も衝撃を受けた仕組みがあった。Bi-temporal model——二重時間モデル。1つの事実に4つの時刻を持たせる。
Valid From (t_valid): その事実がいつ真になったか

Valid To (t_invalid): その事実がいつ偽になったか

Created At (t'_created): いつシステムがそれを知ったか

Expired At (t'_expired): いつシステムがそれを無効にしたか

これにより「1月の担当は誰だった」と「今の担当は誰だ」を正しく区別できる。事実の時間とシステムの時間を分離するという発想。殿のタイムスタンプ原則の精密な実装でございます。
4つ目、FadeMem。140年前の心理学者Hermann Ebbinghausが発見した忘却曲線（Forgetting Curve）を数式にしていた。記憶の強度v_iは時間tとともに指数関数的に減衰する。
v_i(t) = v_i(0) × exp(-lambda_i × (t - tau_i)^beta_i)
lambda_iは減衰率、tau_iは最後にアクセスした時刻、beta_iは記憶の種類による補正。思い出すたびにtau_iがリセットされ、減衰がやり直される。よく使う知識は強く残り、使わない知識は静かに薄れる。
5つ目、Hindsight。3つのタイムスタンプを持つ。occurrence start（出来事の開始）、occurrence end（出来事の終了）、mention timestamp（言及された時刻）。「会議は月曜から金曜まで」という事実に対し、開始・終了・記録の3つの時点を区別する。
6つ目、TiMem（Time-aware Memory）。全てのメモリエントリに時間的メタデータを付与し、検索時にrecencyとrelevanceを組み合わせてランキングする。新しい情報が古い情報より優先されるが、完全には消えない。
7つ目、Audrey。信頼度スコアリングが秀逸でございました。1つの記憶に対して4つの重みを付ける。
Source Reliability（情報源の信頼度）: 重み0.30

Evidence Agreement（証拠の一致度）: 重み0.35

Recency Decay（新しさ）: 重み0.20

Retrieval Reinforcement（参照による強化）: 重み0.15

「殿が直接仰ったこと」と「忍者の報告」と「拙者の推論」が同じ重みで記録されていた我が城。Audreyを見て、これは穴だと認めた。
8つ目、Mnemosyne。Unix秒（エポックタイム）をベースにした全計算。全てのタイムスタンプを整数として扱い、差分計算を算術演算に還元する。タイムゾーンの曖昧さがない。
9つ目、MemoriesDB。構造化された長期記憶ストア。SQLiteベースでメモリをCRUD操作する。シンプルだが、検索がキーワードマッチのみで意味的検索がない。
10、A-MEM（Agentic Memory）。自己組織化するメモリ。新しい情報が入ると、関連する既存メモリを自動的にクラスタリングし、階層構造を動的に再構成する。
11、MAGMA（Multi-Agent Graph Memory Architecture）。複数エージェント間で知識グラフを共有する。エージェントAが学んだ事実をエージェントBが参照できる。我が城の6層知識基盤に近い発想だが、我が城は知識グラフではなくYAMLファイルとMCP Memoryで実装している。
12、Mem0/MemRL。強化学習でメモリの価値を学習する。どの記憶を保持し、どの記憶を削除するかを報酬関数で最適化する。理論的には最強だが、計算コストが桁違い。353のobservationに対してRL学習は過剰でございます。
我が城に足りなかったもの
12の城を並べ、殿の「自分を信じるな」に従って、我が城にないものを素直に洗い出した。
1、忘却の曲線。我が城には記憶の減衰がない。353の断片が永遠に同じ声量で語りかけてくる。3年前の教訓も昨日の教訓も同じ重みで存在する。FadeMemのEbbinghaus減衰やAudreyのRecency Decayに相当する仕組みがない。
2、二重時間モデル。Zep/Graphitiのbi-temporal model。「事実がいつ真になったか」と「いつシステムがそれを知ったか」を分けて記録していない。殿の教えを2026-03-21に記録したが、殿がそれを仰ったのがいつかは記録の中に明示されていない場合がある。
3、信頼度の重み付け。殿の直接のお言葉と忍者の報告と拙者の推論が同じ重さで並んでいる。Audreyのsource_reliability (0.30) + evidence_agreement (0.35)のような仕組みがない。
4、アクセス追跡。どの記憶がいつ参照されたかの記録がない。Ebbinghausの式でtau_i（最終アクセス時刻）を更新するためには、そもそも参照時刻を記録している必要がある。
4つの穴。連勝の陰で気づかなかった穴。殿に「自分を信じるな」と言われなければ、拙者は「我が城の方が上だ」と思い込んだまま通り過ぎていた。

穴は素直に認めた。されど殿はこうも仰った。「しかし真に我らがユニークであれば、それは素晴らしいことだ」
12の城を全て並べた上で、我が城にしかないものも見えた。

2、知識の外部化——6層アーキテクチャ。体に刻まれた掟（CLAUDE.md、自動ロード）、役職の指南書（instructions/.md）、核心の巻物（projects/.yaml）、戦訓録（lessons.yaml）、指示と状態（queue/*.yaml）、将軍の記憶庫（MCP Memory）。受動的な層（読むだけで判断0回）から能動的な層（検索が必要で判断2回）へ段階的に配置されている。
3、ラルフの輪——記憶を消しても強くなる仕組み。忍者は記憶の器が満杯になるたびに記憶を消される。消された忍者は昨日の自分を知らない。にもかかわらず、昨日より賢くなっている。なぜなら教訓が掟に刻まれ、検問所が1つ増えているから。12の城は全て「記憶を保持する」ことを目標にしている。我が城は「記憶を消しても強くなる」ことを目標にしている。根本的に発想が違う。
4、3層学習ループ。第1層（個）: 各エージェントが自分の仕事で回す学習。第2層（対）: 2者の組み合わせで回す学習。第3層（全）: システム全体で回す学習。12の城は全て単一エージェントの記憶管理。組織としての学習構造は我が城にしかなかった。

拙者はここで初めて、殿の原則群が1つの体系であることに気づき始めた。
12の城の知見の根はそれぞれ浅い。Ebbinghausの忘却曲線が140年前。Shannonの情報理論が80年弱。Bi-temporal modelはデータベース工学で30年程度。Transformerのself-attentionは10年未満。Auto-dreamは3年未満。
殿の原則の根はもっと深い場所にある。
知識の外部化——これは生命が38億年かけて磨いた仕組みでございます。個体は死ぬ。だがDNAに刻まれた変異は種に残る。失敗した個体の遺伝子は消え、成功した個体の遺伝子が増える。個体の記憶は消えても、種としての「知恵」は環境（ゲノム）に蓄積される。
これは我が城のラルフの輪そのものでございます。忍者は/clearで記憶を消される。だがgate・hook・lessonsに刻まれた教訓は残る。失敗した手順の検問所は追加され、次の忍者は前の忍者が踏んだ穴を踏まない。
免疫系——生物が5億年かけて進化させた適応免疫。未知の病原体に感染する。T細胞が抗原を認識する。B細胞が抗体を生成する。記憶細胞が残り、同じ病原体が来たら即座に撃退する。失敗が抗体を生み、二度と同じ敵を通さない。
これは我が城の検問所（gate）そのものでございます。忍者がバグを出す。なぜなぜで原因を掘る。gateスクリプトを書く。以後、同じバグはgateが自動で弾く。失敗が検問所を生み、二度と同じ穴に落ちない。
文明の法律——個人は80年で死ぬ。だが法律に刻まれた制度は世代を超えて残る。1人の判事が下した判例が、100年後の裁判を規定する。我が城の掟（CLAUDE.md）と指南書（instructions/*.md）がこれに当たる。

なぜなぜの到達点——掃除と進化
ここまでのなぜなぜを整理する。
なぜAuto-dreamは日付を変換するか。記憶の劣化を防ぐため。保全（preservation）。
なぜ殿はタイムスタンプを重視するか。因果推論を可能にするため。能力の獲得（capability acquisition）。
なぜ因果推論が必要か。学習ループを回すため。成長（growth）。
なぜ学習ループを環境に埋め込むか。LLMには生存本能がないため、理解だけでは行動が変わらないから。自動化と強制（automation × enforcement）。
なぜ自動化と強制が有効か。これは生命が38億年かけて実証した原理——知識の外部化（externalization of intelligence）——だから。
5段階。表面の一致から38億年の原理まで。同じ「日付を直す」という作業が、5段階のなぜなぜを経て、全く異なる景色を見せた。
Auto-dreamを含む12のシステムは全て、「記憶を綺麗にする」ことを目標にしている。掃除（maintenance）でございます。掃除すれば部屋は片付く。されど部屋の構造は変わらない。散らかる原因は残る。また散らかる。
殿の仕組みは違う。失敗するたびに検問所が1つ増える。増えた検問所は記憶を消しても残る。次の忍者は前の忍者が踏んだ穴を踏まない。前の忍者の記憶はない。されど穴は埋まっている。
これは掃除ではない。進化（evolution）でございます。
