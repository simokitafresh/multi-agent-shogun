- 立場: **既存のprovenance設計書(160KB)を参照しない。ゼロから書く。** 既存の用語・工程番号・機構名を持ち込まない

## §1 対象はこれだけである

本番に存在するのは **102個のポートフォリオ**（2026-08-15実測）。

| 種別 | 個数 | 中身 |
|---|---|---|
| standard | 24 | **銘柄を直接持つ** |
| FoF | 78 | **他のポートフォリオを持つ** |

FoFが持つ相手はstandardのこともFoFのこともある。**それだけ。** 深さは本番最大4段。

---

## §2 一日ぶんの計算は3行で書ける

ある日 `d`、あるポートフォリオ `P` の「銘柄別比率」を `W(P, d)` と書く。

**規則はこの2つしかない。**

```
規則1（standard）: W(P,d) = そのPFの判定が選んだ銘柄に 1.0
規則2（FoF）:      W(P,d) = Σ_i  w_i × W(C_i, d)
                            （C_i = i番目の構成PF、w_i = その目標比率、Σw_i = 1）
```

規則2の右辺に `W(C_i, d)` がまた出てくる。**これが「入れ子」の正体である。** 特別な機構ではない。同じ規則をもう一度使うだけ。

**終端**: standardに当たれば規則1で止まる。standardは必ず銘柄を返すので、有限段で必ず終わる。

## §3 手で計算してみる

### §3.1 standard 2個

| PF | その日の判定 | W |
|---|---|---|
| A | SPY | `{SPY: 1.0}` |
| B | 現金退避 → Cash | `{Cash: 1.0}` |

### §3.2 leaf FoF（standardだけを持つFoF）

FoF `F1` が A を 0.6、B を 0.4 で持つ。

```
W(F1) = 0.6 × {SPY:1.0} + 0.4 × {Cash:1.0}
      = {SPY: 0.6, Cash: 0.4}
```

### §3.3 nested FoF（FoFを持つFoF）

FoF `F2` が F1 を 0.5、A を 0.5 で持つ。

```
W(F2) = 0.5 × {SPY:0.6, Cash:0.4} + 0.5 × {SPY:1.0}
      = {SPY: 0.3+0.5, Cash: 0.2}
      = {SPY: 0.8, Cash: 0.2}
```

**合計は必ず1.0になる。** ならなければどこかが壊れている。**この検算は暗算でできる。**

### §3.4 深さ4でも同じ

`P4 → P3 → P2 → P1 → 銘柄` と続いても、規則2を4回使うだけ。**新しい概念は一つも要らない。**

## §4 AsIs — 何が起きているか

### §4.1 同じ `W(P,d)` を作る道が2本ある

| 道 | 中身 |
|---|---|
| **道A: その場で展開** | 規則1と2をその場で適用して計算する |
| **道B: 保存値を読む** | 過去に計算した `W` を保存しておき、それを読む |

**2026-08-15の実測（15,768組＝(PF, 日)の組）**:

```
一致     14,955
不一致      813   ← 5.2%
  ├ 銘柄集合が違う   731（FoF 434 / standard 297）
  ├ 比率が違う        64（FoF 64）
  └ 保存側にあり展開側が空  18（standard 18）
```

**同じ日の同じPFについて、道Aと道Bが違う答えを出す。** これが本番事故の正体である。5.2%は誤差ではない。**銘柄そのものが違うものが731件ある。**

### §4.2 なぜ2本あるのか

速度のためである。道Bは再計算を省ける。**だが「速い道」と「正しい道」が別物になった時点で、速度の話ではなくなっている。**

### §4.3 現状で守りが効いていない

| 機構 | 状態 |
|---|---|
| 確定月の凍結台帳 | **0行**（2026-08-10 `cmd_4287` γ5 cutoverの「ledger再基線」= 殿裁可済みの意図的操作） |
| 台帳の番人 | **detect-onlyへ降格**（`c13a56fe` 2026-08-12。以前は台帳の値を返して上書きを拒んだが、今は計算値をそのまま返す） |
| 日次ETL | 毎日 `mode=PORTFOLIO, start=2000-01-01` で**2000年からの全履歴を再生成** |

∴**過去の確定した判定が、毎日書き換わり得る。** 実測: 8/13=1751件、8/14=8626件、8/15=8761件。

### §4.4 AsIsを一文で

> **同じものを2通りに計算し、どちらが正しいか決めておらず、違っても止まらない。**

## §5 ToBe — どうあるべきか

### §5.1 原則1: `W(P,d)` の定義は1つだけ

**規則1と規則2が唯一の定義である。** 保存値は「定義」ではなく「定義の計算結果の控え」にすぎない。

∴**控えと定義が食い違ったら、定義が勝つ。** 控えを信じて定義を上書きしてはならない。

### §5.2 原則2: 控えを使ってよいのは「一致を証明できる時」だけ

控えを速度のために使うなら、**使う前に定義と一致することを確かめる。** 確かめずに使うのは、速度ではなく賭けである。

現在の実測では**5.2%が不一致**なので、**今は控えを使ってはならない。**

### §5.3 原則3: 合計1.0は毎回検算する

§3で見たとおり、これは暗算でできる。**できる検算を省く理由はない。** 合計が1.0から外れたら、その時点で止める。

### §5.4 原則4: 確定した過去は、定義が変わらない限り変わらない

同じ入力に同じ規則を当てれば同じ答えが出る。**過去の判定が今日変わったなら、入力か規則が変わったのである。** どちらが変わったかを言えないなら、変えてはならない。

### §5.5 ToBeを一文で

> **計算は1通り。控えは一致を確かめた時だけ使う。合計1.0を毎回検算する。過去が変わったら理由を言えるようにする。**
