## §1 変動の監視（プロセスは安定しているか？）

問題: GATE CLEAR率99.7%で「順調」に見えるが、微小な劣化を見逃していないか？

### Shewhart管理図 (p-chart)

- **何**: 不良率を3σ限界で監視。UCL/LCLの外に出たら異常
- **強み**: シンプル。大きな変動を即検知
- **弱み**: 小さな持続的変化には鈍感
- **我々のデータ**: p̄=0.003, n=30 → UCL=0.033。30cmd中1件FAILでやっとアラート。感度不足
- **出典**: Wikipedia "Statistical process control", ASQ

### CUSUM (累積和管理図)

- **何**: 目標値からの偏差を累積。閾値(h)を超えたらアラート
- **強み**: 小さな持続的変化に高感度。Shewhartが見逃す「じわじわ劣化」を捕捉
- **弱み**: パラメータ(k, h)の設定に知識が必要。突発的な大変動にはShewhartが速い
- **我々のデータ**: FAIL率0.3%→1%への微増を5-10cmd以内に検知可能（Shewhartでは不可能）
- **出典**: IEEE "CUSUM-EWMA for Anomaly Detection"

### EWMA (指数加重移動平均)

- **何**: 最近のデータに大きな重みを付けた移動平均。重み係数λで感度調整
- **強み**: パラメータ1つ(λ)で感度を連続調整。最近の変化に敏感
- **弱み**: λの選択が結果に大きく影響
- **我々のデータ**: λ=0.2程度で直近5-10cmdに重点。累積率の「慣性」を排除
- **出典**: IEEE "CUSUM-EWMA Combination", SciencePress 2025

### CUSUM + EWMA 複合

- **何**: CUSUMとEWMAを組み合わせた手法。IEEE研究(2015)で提案
- **強み**: 両方の長所を活かし、単純な異常と複雑な異常の両方に対応
- **弱み**: 実装が複雑。パラメータが増える
- **判定**: 現時点では過剰。まずCUSUM単体で十分
- **出典**: IEEE Xplore "A combination of CUSUM-EWMA for Anomaly Detection in time series data"

## §2 変化の検知（いつ何かが変わったか？）

問題: cmd介入後、「本当に変わった」のか「たまたま」なのか判断できない

### Change Point Detection (変化点検出)

- **何**: 時系列の統計的性質（平均・分散・分布）が変化した点を自動検出
- **オフライン版**: 全データ取得後に最適な変化点を見つける（事後分析用）
- **オンライン版**: リアルタイムでデータが来るたびに判定（監視用）
- **我々への適用**: cmdの効果を「この時点で変化が起きた」と統計的に示せる
- **出典**: ScienceDirect "Time series anomaly detection via temporal relationship graphs" (2025)

### SPRT (逐次確率比検定 — Wald)

- **何**: サンプルを1つずつ見て「仮説Aか仮説Bか」を逐次判定。最適な早期停止
- **強み**: 必要最小限のサンプルで判定。固定サンプルサイズの検定より効率的
- **弱み**: 2つの仮説を事前に定義する必要あり
- **我々への適用**: 「FAIL率は0.3%のままか、1%に悪化したか」をcmd1つずつ見て判定。
  gate改善cmd投入後「効果あり/なし」を最速で結論できる
- **出典**: Wikipedia "Sequential probability ratio test", Abraham Wald (1945)

### Western Electric Rules (ウェスタンエレクトリック・ルール)

- **何**: SPC管理図上の8つのパターンルール（例: 7点連続で平均の同じ側、等）
- **強み**: 統計的検定と補完的。パターンベースで「何か怪しい」を早期検知
- **我々への適用**: 既存gateに組込可能。「5cmd連続で同じ忍者がFAIL」等のルール化
- **出典**: ASQ, Western Electric Handbook

## §3 介入の効果測定（cmdは効いたか？）

問題: cmd_1336でautofix追加。効果は？累積数値では「前からずっと良い」に埋もれる

### 中断時系列分析 (ITS: Interrupted Time Series)

- **何**: 介入前後の傾斜(trend)とレベル(level)の変化を統計的に検定
- **強み**: 対照群が不要（我々のように全体に適用する場合に最適）
- **弱み**: 介入以外の要因による変化との区別が難しい（交絡）
- **我々への適用**: cmdの前後でFAIL率・WA率の傾斜変化を測定。最も直接的に使える
- **出典**: Causal inference in software engineering research

### 差分の差分法 (Difference-in-Differences)

- **何**: 介入群と対照群の差の差を測定
- **強み**: 交絡因子を排除しやすい
- **弱み**: 対照群が必要 → 我々の場合、対照群がない（全cmdに同じgateを適用）
- **判定**: 適用困難。忍者間比較には使えるかもしれない（gate適用前後の忍者A vs B）
- **出典**: Causal inference methods review

### Bayesian Before/After

- **何**: 事前分布（介入前の信念）を事後データで更新
- **強み**: 小サンプルでも使える。不確実性を定量化できる
- **弱み**: 事前分布の設定に主観が入る
- **我々への適用**: 「このgateのFAIL率は5%だろう」→cmd後のデータで更新→「2%に下がった（95%信用区間: 1-4%）」
- **出典**: Bayesian Sequential Analysis, Stanford CCRMA

## §4 ボトルネック特定（どこが制約か？）

### TOC (制約理論 — Goldratt)

- **何**: 全体のスループットはボトルネック（制約）で律速される
- **5つのステップ**: 制約を特定→制約を徹底活用→他を制約に従属→制約を強化→繰り返し
- **我々への適用**: WA率40%の家老レビューが制約か？忍者のidle時間が制約か？
  TOCの問い: 「全体のcmd完了速度を律速しているのは何か？」
- **出典**: Goldratt "The Goal", ASQ "How to Compare Six Sigma, Lean and TOC"

### Six Sigma DMAIC

- **何**: Define(定義)-Measure(計測)-Analyze(分析)-Improve(改善)-Control(管理)
- **我々との対応**:
  - Define = なぜの起点（問題を定義）
  - Measure = 確認する（データを取る）
  - Analyze = なぜを掘る（根本原因分析）
  - Improve = cmd起票（改善を実施）
  - Control = gate/hook（改善を維持）
- **気づき**: 殿が到達した deepdive サイクルは DMAIC と同じ構造。独立に同じ結論に達した
- **出典**: iSixSigma, ASQ

### Lean (ムダ排除)

- **何**: 顧客価値に寄与しない7つのムダを排除
- **7つのムダ**: 過剰生産/待ち/運搬/加工/在庫/動作/不良
- **我々への適用**: idle時間=「待ちのムダ」。Read before Write失敗=「不良のムダ」
- **出典**: Toyota Production System, Lean Enterprise Institute

## §5 信頼性予測（次いつ壊れるか？）

### MTBF (平均故障間隔)

- **何**: 故障間の平均時間（またはcmd数）。MTBF = 1/故障率
- **我々への適用**: GATE FAIL間のcmd数を計測。MTBF=333cmd（FAIL率0.3%から）
  MTBFの推移そのものが品質改善の指標になる
- **出典**: Reliability Academy, Vicor Power "Reliability and MTBF Overview"

### バスタブ曲線

- **何**: 初期故障期→安定稼働期→摩耗故障期の3フェーズ
- **我々への適用**: 新gate導入直後のFAIL多発は「初期故障」と認識できる。
  安定稼働に入った後のFAIL増加は「新たな問題」のシグナル
- **出典**: Wikipedia "Bathtub curve"

### ソフトウェア信頼性成長モデル (SRGM)

- **何**: テスト・運用を続けるとバグが減少していくことをモデル化
- **代表モデル**: 指数型(Musa), 対数型(Musa-Okumoto), S字型(Gompertz)
- **我々への適用**: GATE FAILの累積数が成長曲線に乗っているか？
  乗っていれば「改善は収束に向かっている」。外れたら「新たな問題クラス出現」
- **出典**: CMU "Software Reliability"

## §6 車輪の選定基準

殿の原則: (1)今よりマシか？ (2)新しい長期問題を生まないか？

### 我々のデータの特徴
- **二値データ**: GATE CLEAR/FAIL（比率データ）
- **小さなFAIL率**: 0.3%（1000cmd中3件）
- **介入(cmd)が頻繁**: 月に数十のgate改善cmd
- **対照群なし**: 全cmdに同じgateを適用
- **サンプルは逐次的**: cmdが1つずつ完了する

### 特徴に合う車輪の優先順位
1. **CUSUM** — 二値×小FAIL率×逐次 にぴったり。p-chartより高感度
2. **ITS** — 対照群不要×頻繁な介入 に最適
3. **MTBF** — 二値×信頼性推移 の直接指標
4. **SPRT** — 逐次×早期判定 でcmd効果を最速確認
5. **バスタブ曲線** — 新gate導入後の初期FAIL解釈に使える

### 採用しない（今は）車輪とその理由
- **差分の差分法**: 対照群がないため適用困難
- **CUSUM+EWMA複合**: 現時点では過剰。単体で不十分と判明してから
- **Lean**: 概念は既に適用済み（idle=ムダ等）。新たな車輪は不要
- **SRGM**: データ量が十分になってから（現在1104cmd、もう少し）
