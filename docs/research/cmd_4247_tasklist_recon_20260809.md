## 1. 結論

1. Dashboard has no single dashboard API. The FE composes three API paths: `/api/signals` for the signal/current holding card, `/api/performance/{portfolio_id}` for the long chart, and `/api/mtd/{portfolio_id}` for daily MTD. T-α7 must therefore name the API contract and its three downstream FE consumers; “dashboard系API 1ファイル” is presently under-specified.
2. The global execution-timing toggle is a shared context with fixed initial `CLOSE` and localStorage hydration. It is consumed by Dashboard, Total Return, MTD, Monthly Returns, Monthly Trade, Annual Returns, Compare, Compare Summary, Drawdowns, Rolling Returns, and metrics tables. T-β1 must change the provider fallback/initial state and test the full consumer matrix, not only `monthly-returns-table.tsx`.
3. Standard momentum already has a reusable daily-series window implementation: `calculate_composite_momentum_vectorized()` delegates each lookback to `calculate_momentum_vectorized()` (`backend/app/services/vectorized_momentum.py:7-72`), and `MomentumCache.get_composite_momentum()` is a compatible cached implementation (`backend/app/services/momentum_cache.py:377-426`). FoF currently feeds selection from component monthly-return rows and uses `monthly_return_open` fallback to close (`backend/app/jobs/recalculate_fof.py:624-631`); this is not a daily chain-link NAV. `expand_portfolio_to_tickers()` is point-in-time holding expansion, not a daily NAV evaluator (`backend/app/services/price_ratio_impl.py:1365-1403`). T-γ1 needs a new NAV construction layer; T-γ2 can reuse the standard window function through an adapter.
4. `effective_start_date` is currently populated by copying `rebalance_decision_date` in the initial-ledger plan (`backend/app/services/signal_decision_ledger.py:554-569`) and by copying `target_date` for corrections (`:329-340`). `signal_flush._flush_batch()` reconciles and writes Signal rows but does not create or pass an execution boundary (`backend/app/jobs/flush/signal_flush.py:318-354`). T-δ1 must locate the post-calculation/first-trading-day execution caller; changing the resolver alone would not fix the write path.
5. At HEAD, `_cleanup_before_recalculate()` deletes Signal rows when `delete_signals=True`, then unconditionally deletes seven portfolio-dependent tables for all modes, including `MonthlyReturn` (`backend/app/jobs/recalculate_fast.py:1108-1135`). It conditionally deletes only `TickerMonthlyReturn` for all-PF `FULL`/`TICKER` (`:1137-1143`). Therefore T-ε1 must gate the seven-table list by `mode=portfolio`; T-ε3 must separately guard the all-table/full-rebuild path. The current code does not have a mode guard for the seven-table list.
6. The backend test harness is root-qualified: `backend/tests/conftest.py:9-13` loads `backend.tests.pytest_duration_ledger_plugin` and appends the backend path. Running from `backend/` fails plugin import (`No module named 'backend'`); the working invocation is from repo root with `PYTHONPATH=.` and `pytest backend/tests ...`. A collect-only probe for `return_status` then completed discovery with `no tests collected (1902 deselected)`, rc=5. The tasklist commands omit this cwd/PYTHONPATH prerequisite and currently have no exact test target for most new keywords.
