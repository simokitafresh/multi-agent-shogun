§4 未決4項 — 殿の裁定待ち（各項に将軍の推薦付き）

1. 案Aの一覧テーブルに載せる列の選定（全設定項目は載らない。何を俯瞰したいか）
将軍の推薦: PF名 / フォルダ / Top N / Rebalance Trigger / Lookback概要（期間数のみ） / Benchmark / 操作（Edit・複製・削除）。理由: 運用時の確認頻度が高い判定系設定を優先し、Absolute Momentum・Safe Haven等の詳細は単票で見る。列は後から足せる（最小から作る=LS104）。
2. 単票エディタの2カラムカード構成を表形式へ寄せるか、現行維持か
将軍の推薦: 現行維持。理由: 一覧性問題の主因は「102件を1件ずつしか見られない」ことで、単票自体の形ではない。案Aで一覧が入れば単票の役割は編集のみ。差分最小・回帰リスク最小。
3. FoF Weight Breakdownの既定=閉で問題ないか（as-of確認の頻度）
将軍の推薦: 既定=閉、ただしas-of日付だけは一覧行に常時表示。理由: 縦を支配する本体（Component×Target%）は低頻度、鮮度確認（as-of）は高頻度と推定されるため分離。
4. 一括操作（複数PF選択→フォルダ移動 / visibility変更）の要否
将軍の推薦: 初期スコープ外（案A-Dの後の独立cmd）。理由: 一覧化だけで俯瞰・到達の主課題は解消し、一括操作は誤操作リスク（本番設定の大量変更）を伴うため、一覧運用の実感を得てから設計する方が安全。
