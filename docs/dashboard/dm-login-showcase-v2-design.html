§2.4 ブラックアウト表現 — 殿裁定 12:58「日時は書かない・期待感+note 誘導」

帯(サインインカード上部、active=true)

August is closed. New signals for September are computed.
The password unlocks them — announced on note.
8 月のシグナルは確定。9 月のパスワードは note で発表します。お楽しみに。

ボタン「Get notified on note →」。直下に "New month's holdings are ready for 45 portfolios"(EP の n_signals、保有内容は出さない)。月名は series_end から自動。

禁則と判定

  • カウントダウン・日時・「soon / early September / 近日」を使わない(発表タイミングは殿の裁量)
  • 判定: max(password_expires_at) < today ∧ last_rotated_at ≤ expires_at。rotate で自動解除。EP は {active, month_closed, n_signals} のみ
  • 失効 401: 「This password has expired ／ このパスワードは失効しました」+同じ note 誘導。入力欄は残す
  • 通常時は帯なし、カード内 1 行 "This month's password is on note →"

§2.5 摩擦優先 — 殿参照 10:21(note「入口を変えただけで登録 1.6 倍」)

記事の結論: 使われない理由は魅力不足ではなく摩擦。効いたのは説明・特典・文言ではなく経路修正(着地ページ・ボタンを画面内へ)。区間で数えると一箇所が突出して悪く、たいてい思っていた場所と違う。→ ショーウィンドウ(魅力)より先に摩擦除去と区間計測を置く。

#摩擦候補(AsIs)対処(ToBe)計測区間

§2.6 描画・更新方針 — 殿下問 12:54「daily 更新か、期間明記の static か」

観点AsIsToBe
数値の鮮度metrics は毎日再計算(calculated_at 08-30)だが系列は月末基準(end 07-31)=月 1 回しか変わらないEP cache 1h、表示は「Data through {series_end}」明記。daily の見た目更新は不要(値が変わらない)
描画"use client" CSR、HTML 本文は空(title のみ)ISR: server component 化、revalidate 86400+月末再計算後の on-demand revalidate。初回 HTML に数値・H1・脚注を焼き込む
SEOrobots.txt / sitemap / metadata なし=検索エンジンから空/login に metadata(EN)、robots.txt・sitemap 追加、/login のみ index 許可
動線/→/login replace の白画面リスク(F1)ISR で /login が即描画=F1 の解消と同じ手

結論: 「static に見える ISR」= 期間明記+SEO 可+自動更新。CSR の daily fetch は SEO ゼロで値も変わらないので採らない。「realtime」とは書かない(月次データを日次に見せない)。P2b AC: 本番 /login の HTML に表の数値が含まれる・脚注に Data through 日付・metadata description(EN)。
